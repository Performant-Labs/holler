# Holler protocol v2

Holler is a **talk circuit**. This page is the **v2** application
protocol: **JSON-RPC 2.0** messages on a **WebSocket** between the
**hub** and the **body**. This file is **canonical**: ADRs decide why,
stories implement this page. It supersedes [v1](v1.md) (v1 is not
ported; see [ADR 0002](../adr/ADR-0002.md)).

## 0. Guiding documents

The v2 object model and envelope are **reused verbatim** from three
published specs; Holler adds only the thin circuit on top. Pinned
revisions:

| Document | Revision | URL | Role in v2 |
| --- | --- | --- | --- |
| A2A | **v1.0.1** (tag `v1.0.1`, published **2026-05-28**; 1.0.0 was 2026-03-12) | <https://a2a-protocol.org/latest/specification/> | The **object model**: `Message`, `Part`, and the task-state vocabulary. Reused **verbatim** on the inward wire. |
| ACP | **v2** (crate `agent-client-protocol` 2.1.0) | <https://github.com/agentclientprotocol/agent-client-protocol> | The **body hop**: the body's driver maps `session/prompt`/`session/update`/`session/cancel` 1:1 to ACP. ACP's `stopReason` is the source of truth. |
| JSON-RPC | **2.0** | <https://www.jsonrpc.org/specification> | The **envelope**: requests, notifications, responses, error objects, and the standard error codes. |

## 1. Transport

- **WebSocket text frames.** Exactly **one JSON-RPC 2.0 message per frame**.
- **No batches.** A JSON **array** at the top level (a JSON-RPC batch) is **rejected with `-32600`** and the socket is closed. Batching is deferred to a future protocol version.
- **Binary frames are not a message.** A binary frame is rejected with `-32600` (see §8).
- **Loopback is plain `ws`; off-loopback is `wss`.** Plain `ws` is **loopback only** (`127.0.0.1` / `::1`). Off-loopback (LAN, tailnet, public) is **`wss`** via a TLS proxy ([ADR 0006](../adr/ADR-0006.md)). The listen address is user-settable (repeatable); default **`127.0.0.1:41807`**, IPv6 `[::1]:41807`. Do not default to `localhost`.
- Any underlay (LAN, SSH tunnel, Tailscale, public IP) may create the TCP path. It is not Holler auth, not Holler addressing, and **not Holler encryption**.

## 2. Envelope

JSON-RPC 2.0. Four wire shapes (see `holler_proto::envelope`):

| Shape | Fields | Notes |
| --- | --- | --- |
| Request | `jsonrpc`, `id`, `method`, `params`? | `id` present |
| Notification | `jsonrpc`, `method`, `params`? | **no `id`** |
| Response | `jsonrpc`, `id`, `result` | `id` echoes the request |
| Error | `jsonrpc`, `id`, `error` | `error: {code, message, data?}` |

**Correlation ids are string ULIDs with a minting-prefix:**

- `h-` — minted by the **hub**
- `b-` — minted by the **body**

The prefixes guarantee the two sides' id spaces **never collide** (a
`b-` id can never equal an `h-` id). A **reply reuses the request's
`id`** — that is what correlates a response to its request (this replaces
v1's `id` reuse on the envelope). **Notifications carry no `id`.**

`id` is **stringly-typed on the wire**; the prefix is a minting
convention, not a wire field a peer must validate. A response whose
`id` does not match any outstanding request is an **unmatched response**
(see §8 / §11).

## 3. Connection

```
connect → circuit/join → (hub closes)      ← first pairing only
connect → circuit/authenticate → circuit/hello (both ways) → talk
```

1. **`circuit/join`** — legal **only** as the **first frame on a fresh socket**, and **only** on a socket that has not sent `circuit/authenticate` (a socket sends join or authenticate, never both). It redeems a one-time **join secret** for a `client_id` + long-lived `credential`. On success the hub **closes the socket after replying** — join never leads into talk on the same socket; it is a one-shot bootstrap. A new join token is only for a new pairing.
2. **`circuit/authenticate`** — the **first frame** on a normal (re)connect, presenting the **credential** (not the join secret). Do not put the credential in a logged URL query string.
3. **`circuit/hello`** — sent **both ways** after authenticate. Carries `protocol` / `protocol_min` / `protocol_max` plus the role-appropriate capabilities document (§5). **`hello.protocol ≠ 2` → error `-32000 unsupported_version` and the socket closes. No silent downgrade.**
4. After **both** hellos, `session/…`, `query/…`, and `circuit/ping` are legal.

**Reconnect** re-authenticates with the credential again and re-sends a
complete, fresh `circuit/hello` **and** `session/presence` on every
successful (re)connect — the peer treats each advertisement as
authoritative, never a merge with prior state (the v1 reconnect
contract, carried over).

## 4. Method catalog

| Method | Kind | Direction | params | result |
| --- | --- | --- | --- | --- |
| `circuit/join` | request | body→hub, first frame on a fresh socket | `{secret, hostname}` | `{client_id, credential}`; hub **closes the socket** after replying |
| `circuit/authenticate` | request | body→hub, first frame | `{token_id, credential, hostname}` | `{ok: true}` |
| `circuit/hello` | request | both, after auth | the hello document (§5) | `{}` |
| `circuit/ping` | request | both | `{}` | `{hostname, ts}` |
| `circuit/superseded` | notification | hub→old socket | `{}` | — (then the hub **closes** it) |
| `query/status` | request | both | `{}` | the status document (§5.1) |
| `query/caps` | request | both | `{}` | the caps document (§5.2) |
| `query/support` | request | both | `{feature}` | the support answer (§5.3) |
| `query/protocol` | request | both | `{version?}` | `{session:2, min, max, asked?, ok?}` |
| `session/presence` | notification | body→hub | `{hostname, sessions:[{name, harness, state, mode, harness_session_id?}]}` — `state` names are A2A's | — |
| `session/prompt` | request | hub→body | `{session, message, meta?}` (`message` is an A2A `Message`, `role:"user"`) | `{stopReason, state, message}` (§6) |
| `session/update` | notification | body→hub | `{session, prompt_id, seq, parts:[Part]}` (a streamed text chunk is a text `Part`; the coalescer merges consecutive text parts) | — |
| `session/cancel` | request | hub→body | `{session}` | `{applied: true}` — sent **only after** the cancel was applied |

`session/cancel` is **control, not a prompt**: it cancels the in-flight
**turn**; the session survives and stays promptable. It never routes into
a model.

### Hello document

A **body's** hello:

```json
{
  "protocol": 2, "protocol_min": 2, "protocol_max": 2,
  "role": "body", "hostname": "kiwi",
  "token_id": "tok_7f3a", "client_id": "cli_19",
  "features": ["interrupt", "presence", "ping", "query"],
  "harnesses": ["opencode"],
  "sessions": [
    {"name": "alpha", "harness": "opencode", "mode": "spawn"},
    {"name": "beta", "harness": "opencode", "mode": "attach"}
  ]
}
```

A **hub's** hello (the hub is a **peer** for status — same document
shape, `role:"hub"`, and it has `harnesses_known` /
`harnesses_confirmed` instead of `harnesses` / `sessions`):

```json
{
  "protocol": 2, "protocol_min": 2, "protocol_max": 2,
  "role": "hub", "hostname": "uranus",
  "features": ["interrupt", "presence", "ping", "query", "roster", "token", "attach", "opencode-http"],
  "harnesses_known": ["opencode"],
  "harnesses_confirmed": ["opencode"]
}
```

**Advertise only what is real.** A body lists a harness only if it can
spawn/attach that adapter on this box. `hello` is a hint;
`query/support` is the check.

## 5. Documents

### 5.1 Status document

One shape, two `role` values (the hub as a peer answers the same
document). **Body:**

```json
{
  "role": "body", "protocol": 2, "protocol_min": 2, "protocol_max": 2,
  "hostname": "kiwi", "connected": true, "token_id": "tok_7f3a",
  "features": ["interrupt", "presence", "ping", "query"],
  "harnesses": ["opencode"],
  "sessions": [{"name": "alpha", "harness": "opencode", "state": "idle"}]
}
```

**Hub:**

```json
{
  "role": "hub", "protocol": 2, "protocol_min": 2, "protocol_max": 2,
  "hostname": "uranus", "listening": "ws://127.0.0.1:41807",
  "features": ["interrupt", "presence", "ping", "query", "roster", "token", "attach", "opencode-http"],
  "harnesses_known": ["opencode"],
  "harnesses_confirmed": [{"id": "opencode", "bodies": ["kiwi"]}],
  "bodies": 1, "sessions": 2
}
```

### 5.2 Caps document

`caps` is `status` **plus** an explicit map of every known feature /
harness → `{ok, kind, how?, reason?}`. A body's view lists the features
and harnesses **it** implements; the hub's view lists `harnesses_confirmed`
(a live body answered `query/support` `ok:true` — an advertisement alone
is not enough) and the protocol features the hub implements.

### 5.3 Support answer

`query/support {feature}` →

```json
{"feature": "opencode", "kind": "harness", "ok": true, "how": "opencode acp"}
```

or, when unsupported,

```json
{"feature": "claude", "kind": "harness", "ok": false, "reason": "no adapter"}
```

`kind` is `feature` | `harness` | `capability`. `ok` is decided by a
**local probe** (adapter + runnable harness), never by asking a model. A
`feature` id outside the vocabulary (§9) → error `-32006 unknown_feature`.

### 5.4 Protocol answer

`query/protocol` (no `version`) reports the range — `{session:2, min,
max}`. With `{version: n}` it answers "can you speak `n`?" →
`{session:2, min, max, asked: n, ok}` where `ok = asked >= min && asked
<= max`. `n` must be a positive integer, else `-32006 unknown_feature`.

## 6. Talk

A **`session/prompt`** request (`{session, message, meta?}`) produces
**zero or more** `session/update` notifications and **then exactly one**
response when the turn ends — the **ACP shape, verbatim**:

```json
// request (hub → body)
{"jsonrpc":"2.0","id":"h-01H...","method":"session/prompt","params":{"session":"io/alpha","message":{... A2A Message, role:"user" ...}}}

// streamed chunks (body → hub), one per turn delta
{"jsonrpc":"2.0","method":"session/update","params":{"session":"io/alpha","prompt_id":"h-01H...","seq":1,"parts":[{"text":"Hel"}]}}
{"jsonrpc":"2.0","method":"session/update","params":{"session":"io/alpha","prompt_id":"h-01H...","seq":2,"parts":[{"text":"lo"}]}}

// exactly one response, when the turn ends
{"jsonrpc":"2.0","id":"h-01H...","result":{"stopReason":"end_turn","state":"completed","message":{... A2A Message, role:"agent" ...}}}
```

- `message` in the response is an A2A `Message` with `role:"agent"`; **`message.parts` is the full reply** — the **coalescer merges consecutive text parts** into one before it is sent, so the agent's reply is one logical text (interleaved `raw`/`url`/`data` parts are kept as their own parts).
- `seq` is a per-`prompt_id` monotonic counter; `prompt_id` is the **request's `id`**, so each `session/update` is correlated to the prompt that produced it.
- **`stopReason` is the source of truth** (the ACP value, carried verbatim). The **A2A terminal `state` is derived from it at the body**, so the A2A bridge is a pass-through:

  | ACP `stopReason` | → A2A terminal `state` |
  | --- | --- |
  | `end_turn` | `completed` |
  | `cancelled` | `canceled` |
  | `error` | `failed` |
  | `refusal` | `rejected` |
  | `max_tokens` | `failed` (with reason) |
  | `max_turn_requests` | `failed` (with reason) |
  | `limit` | `failed` |

- **Cancellation** is a **`session/cancel`** request → a response
  **`{applied:true}`** sent **only after** the cancel was actually applied
  (called ACP `session/cancel` / the OpenCode-HTTP fallback — not merely
  parsed). **That response is the acknowledgement** the interruption path
  wanted (v1's `ack`/`of`). The hub waits for it on a short, RTT-scaled
  timeout.
- **Reconnect** has no durable replay: the only signal is the affected
  session's `state` returning to `idle`; the peer is expected to re-query
  ("ask again"), not rely on durable delivery.

## 7. Presence

`session/presence` is a **notification** (body→hub), sent periodically as
a heartbeat and on every (re)connect:

```json
{"jsonrpc":"2.0","method":"session/presence","params":{"hostname":"kiwi","sessions":[
  {"name":"alpha","harness":"opencode","state":"idle","mode":"spawn"},
  {"name":"beta","harness":"opencode","state":"working","mode":"spawn","harness_session_id":"openc-abc"}
]}}
```

- `state` is an **A2A session state**: `idle` | `working` | `input-required` (ADR 0005 adds `idle` — A2A states are per *task*, Holler presence is per *session*).
- `mode` is `spawn` | `attach`. `harness_session_id` is present for `attach` (the existing harness session being attached to).
- The hub's **roster row is keyed by routable name** (`<label>/<session>`, ADR 0005); `client_id`, peer address, and connection handle are locator fields on that row and may change across a reconnect **without changing the name**.
- A claim for a name held by a **different token** is **rejected** (`-32003 unknown_session`, `data.reason: "name held by another body"`); the **same token** re-advertising its own name always succeeds (the reconnect case). Because presence is **periodic**, a rejected claim is retried on the next beat — a lost presence race (holler-server#243) **cannot recur**.
- The hub **drops stale rows** (presence TTL) into the roster.

## 8. Errors

JSON-RPC **error objects**. Standard codes for framing; **application
codes `-32000..-32099`** carry `data.code` = the Holler string.

| JSON-RPC code | `data.code` | When |
| --- | --- | --- |
| `-32700` | `parse_error` | The frame is not JSON. |
| `-32600` | `invalid_request` | Not a single JSON-RPC 2.0 object — a **batch** (top-level array), a **binary frame**, or a missing/`≠"2.0"` `jsonrpc` field. |
| `-32601` | `method_not_found` | Unknown `method`. |
| `-32602` | `invalid_params` | Schema violation in `params`. |
| `-32000` | `unsupported_version` | `hello.protocol ≠ 2`. Socket closes; **no silent downgrade**. |
| `-32001` | `join_failed` | `circuit/join` secret unknown / already bound / invalidated / revoked / expired — reason in `message`. |
| `-32002` | `unauthenticated` | Bad or revoked `credential`; **any** method sent before authenticate. |
| `-32003` | `unknown_session` | `prompt`/`cancel` to a name not hosted here, **or** a name held by a different token. |
| `-32004` | `not_connected` | A remote `query`/`ping` for a bound token with no live socket. |
| `-32005` | `session_superseded` | A new authenticate for the same token replaced this connection (also sent as the `circuit/superseded` notification; hub closes the old socket). |
| `-32006` | `unknown_feature` | A `query/support` (or `query/protocol` version) id outside the vocabulary. |
| `-32007` | `limit_exceeded` | A hub cap was hit (reserved; used by the caps story). |
| `-32008` | `connection_lost` | The body's socket dropped mid-turn (hub → CLI). |

`data` is an object `{"code": "<data.code>", "reason"?}`. **`-32603`
(internal error) and `-32009` are reserved** and unused in v2. An
**unmatched response** (a response whose `id` matches no outstanding
request) is an application condition: the peer logs and discards it; it
has no JSON-RPC code in v2.

## 9. Feature and harness ids

**Protocol features (v2):**

`interrupt`, `presence`, `ping`, `query`, `roster`, `token`, `attach`, `opencode-http`

**Harness ids** (vocabulary; only `opencode` is a v2 adapter):

`opencode`, `claude`, `codex`, `grok`, `hermes`, `pi`, `cursor`, `copilot`, `droid`, `kimi`, `qwen`, `kilo`, `goose`

(`wait` was dropped in v1 and is not in v2. A new harness is a new **config row** plus a new id — not a protocol bump.) Unknown ids are legal on the wire; `query/support` on an unknown id returns `ok:false` / `-32006` rather than inventing an answer.

## 10. CLI mapping

The complete CLI surface is **normative in [ADR 0003](../adr/ADR-0003.md)**
— this section reproduces its table verbatim so the spec never diverges from
the implementation. Every line in the block below is parsed against the real
clap tree by `crates/holler-cli/tests/docs_cli_test.rs`; the full flag
surface (every verb and flag) is `crates/holler-cli/tests/fixtures/cli-surface.txt`.
A local `query` (no `TARGET`) runs against this process; with a `TARGET` the
hub sends the same command to that body over the wire. `SESSION`/`TARGET`
expand under ADR 0005 (`<label>/<session>`; a bare `<session>` when exactly
one roster row matches).

```text
holler --version | -V                       prints `holler X.Y.Z` (workspace version)
holler --help
global flags on every subcommand:  --debug none|quiet|noisy   --log-format text|json   --json

holler hub serve [--listen HOST:PORT]... [--advertise HOST[:PORT]]
holler hub token mint --label LABEL [--ttl 24h] [--json]
holler hub token list [--json]
holler hub token delete ID            (aliases: rm, remove) — unused token: invalidate the secret
holler hub token revoke ID            (alias of delete for a BOUND token) — cut the body's access now, keep the record
holler hub token ping ID [--json]
holler hub status [--json]
holler hub caps [--json]
holler hub support FEATURE [--json]
holler hub query CMD [ARGS...] [--json]               (local: this hub process)
holler hub query TARGET CMD [ARGS...] [--json]        (remote: TARGET = token id | client id | label | label/session)
holler roster [--json]
holler say SESSION TEXT [--timeout 600s] [--queue] [--json]     refused (-32009) while the turn is busy unless --queue
holler interrupt SESSION [TEXT]                                  cancel; with TEXT, then prompt (one atomic step)
holler answer SESSION CHOICE                                     resolve a held input-required (permission / elicitation)
holler wait SESSION[,SESSION...] [--until STATES] [--after TURN_ID] [--timeout 600s] [--json]

holler body join --server URL --token ID:SECRET
holler body run [--config PATH]
holler body detach
holler body status [--json]
holler body caps [--json]
holler body support FEATURE [--json]
holler body query CMD [ARGS...] [--json]
holler body attach sessions [--endpoint URL]
holler body attach init [--endpoint URL] [--session ID] [--name NAME] [--out PATH] [--force]
```

`--json` is a **global** flag: it prints the result body as exactly one JSON
object on stdout, all diagnostics on stderr. Feature ids are reserved words.

### 10.1 Which wire method each verb sends

`query/*` and `session/*` are the only verbs that carry a wire payload (the
rest are local state or control). Local (no target) runs in-process; remote
routes to the named body.

| CLI | Wire |
| --- | --- |
| `hub status` / `body status` | local `query/status` (no target) or `query/status` to that body |
| `hub caps` / `body caps` / `hub query <target> caps` | `query/caps` |
| `hub support FEATURE` / `body support FEATURE` | local `query/support` / to that body |
| `hub query protocol [N]` / `hub query <target> protocol [N]` | `query/protocol` (highest version) / `{version:N}` (can you speak N?) |
| `say SESSION TEXT` | `session/prompt` to that body (ADR 0005 addressing) |
| `interrupt SESSION [TEXT]` | `session/cancel`, then `session/prompt` when `TEXT` is given |
| `answer SESSION CHOICE` | `session/answer` (held `input-required`) |
| `wait SESSION[,…]` | no wire call: edge-triggered on the hub's roster |
| `roster` | local roster (presence TTL) |
| `hub token ping ID` | `circuit/ping` (bound-socket aliveness; not a query) |

## 11. Not in v2

- **Batches** (a JSON-RPC array per frame) — deferred to a version bump.
- **Binary frames** — rejected (`-32600`); all content is text (a file's bytes are a base64 `raw` Part).
- **Multi-hop routing** — the circuit is 1:1 hub↔body.
- **Model-answered queries** — `query/*` are control, never routed into a model.
- **A2A reachability features** — the HTTP client→server transport, one reachable endpoint per agent, push-notification webhooks, and agent cards. Those assume a reachability the body does not have; they live **only at the hub's outward face** (ADR 0017).
- **A `v0` dialect**, SSH/Tailscale as the app protocol, secrets in logged URLs, PTY multiplexing, and durable replay of a reply that completed while the body was disconnected.
