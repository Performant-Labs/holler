**Date:** 2026-10-12

**Brief reviewed:** `docs/handoffs/850-brief.md`   **Reuse map:** the brief's "Reuse", "Where the code goes" and F1-F12 (no `survey.md`)   **Wireframe:** N/A (`uiSurface: false`)
**Verdict:** PASS

## Summary

PASS, with no block and six warns. The plan extends the right objects at the right layers. The body gets one new `Driver` variant behind the existing enum and the existing session task, and it reuses the adapter through the `HarnessPort` that `holler-cli` injects, so there is no second implementation of delivery and no body-to-adapter edge. The hub, the wire and every golden file stay untouched, and the hub's `send_prompt` stays the one place a prompt passes the hold and the pane gate. The ADR amendment lands first, in the brief's own text. The warns are the support probe's binary lookup (W-1), a source guard that does not cover the new caller (W-2), the cost of the poll (W-3), a stale row's retry (W-4), a window in the drive rule's two writes (W-5) and one wording slip in the ADR text (W-6).

No finding blocks. Confirmed in the tree:

- **Choke point.** `circuit/dispatch.rs::send_prompt` stays the only place a `session/prompt` is built, and a Claude row is a row like any other for the hold and the gate (keyed on the advertised id). The cancel and answer refusals ride the existing `-32004`/`-32003`. Nothing is enforced at a call site or in one delivery variant.
- **Wire.** No field, method, code or golden changes; `harness: claude` on an attach row is the existing presence shape, and the hub's confirm probe goes through the body's existing `query/support`.
- **Crate graph.** `holler-pane` depends on `holler-proto` alone, so `holler-body -> holler-pane` makes no cycle, `holler-pane-testkit` is a dev-dependency only, and ADR-0021 section 5 gets its bullet first (A1). The brief's alternative of a narrow trait in `holler-body` with a CLI wrapper would also work; the hub already depends on `holler-pane` for the same reason, so the chosen shape is the established one.
- **Layer.** The driver reuses `DriverEvent`, `DriverEventStream::new`, `DriverError`, `Status` and `StopReason` and has the public method shapes of `HttpAttachDriver`; `Driver::spawn_or_attach` stays the one place a driver is chosen; `rebind` in `task.rs` changes only to build the driver through that place.
- **Drive rule.** `driver_of` with an empty server list falls to its by-record, by-DRIVEN and by-target rules, so a single process needs no new join. `drive` is reused as written, and `tx_switch`, `plan` and `reconcile` extend the server path's steps and not a copy of them.
- **Size.** `connection.rs` (874) takes at most +2 and `task.rs` (794) at most +10 (wiring only), each with a named overflow location; every other touched file stays under 600 after the change. The new files are sized and named.
- **State.** Nothing new persists; the second write is the existing compare-and-swap; the body row is config. **Secrets.** The driver never calls `login_status` (Acceptance 2), and the fake prints none. **Public repository.** The brief uses placeholders only.
