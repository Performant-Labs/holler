## Summary

PASS. The plan extends the right objects and adds no copies:

- The `--pane` accessors reuse the existing `cli::Usage` and the `Query::resolve` variadic-tail pattern. No second usage-error type is added.
- Every code, guard and port type comes from `holler-pane` (`is_valid_code`, `GridPos::parse`, `EnvVarName::parse`, `Argv::from_json`, `Ports`). No grammar or validator is copied.
- The new `output::Envelope` is a justified new type. `PaneReply`'s own doc says it is not the CLI envelope.
- Process exits stay in `main.rs`, and no hub, proto or golden file changes.

I checked the brief's clap claims on clap 4.6.6 in a scratch crate and they hold.

All 13 findings are `warn`. W-1 to W-5 shape contracts that freeze when this story merges, so T and F should settle them before or during RED. W-9 to W-11 are O decisions. On size (W-13), this slice does not need another split.

Beyond these findings, the plan fits existing patterns. I checked the following:

- **Clap shapes (probe, clap 4.6.6, scratch crate outside the repo).** These parse as the brief says:
  - `say --pane p1 hello` gives the tail `["hello"]`.
  - `say io/alpha --parts-file f` gives `["io/alpha"]`.
  - `say io/alpha hello --queue` and `say --server wss://h alpha hi` still parse.
  - `say io/alpha hello extra` stays a clap `TooManyValues` error, exit 2.
  - `say --pane p1 a b`, bare `say` and `answer --pane p1` all parse, so the accessor has to refuse them (AC 4).
- **Field reshape is contained.** No code outside the three `*_cmd.rs` files builds `Say`, `Interrupt` or `Answer` or reads their fields (checked with grep). The tests drive the binary as a subprocess.
- **No holler-pane edit.** `Hold`'s doc (pane.rs:160-164) already separates the pane-record hold from the prompt hold and sends any pane-derived prompt refusal to `send_prompt`. The brief's decision 10 sentence about `Pane.hold` therefore needs no edit to holler-pane, which stays out of the blast radius.
- **No dependency cycle.** #638 parses envelopes with `serde_json` alone, so the `holler-pane-testkit` dev-dependency creates no path back to holler-cli.
- **Size claims hold.** `main()` (main.rs:84-238) has about 99 code lines, which matches the brief's figure. `cli.rs` is 701 lines and the plan keeps it near 740, under this stack's 800-line attention threshold.
- **Legacy output paths stay.** `print_leaf_result_and_exit` and `query_cmd::print_and_exit_code`/`FetchOutcome` remain the legacy verbs' paths. ADR-0003:69 forbids changing their `--json` shape. So `output.rs` is a deliberate fourth output path for the envelope only, not a duplicate.
