## Summary

PASS. The plan fills the stub that slice a created for this checker, in the module that ADR-0021 sections 5 and 9, the epic, #638 and #660 all name as the one envelope checker. It builds no parallel path. Codes go through `holler_pane::error::is_valid_code`, classes through `class_of` and `ErrorClass::exit_code`, the exhaustive loop through `ALL_CODES`, and framing through `serde_json`'s `StreamDeserializer`. The testkit keeps no code table and no JSON scanner of its own. The dependency direction holds: the testkit gains only `serde_json`, which ADR-0021 section 5 allows by name, and it still does not depend on `holler-cli` or `holler-hub`. All six findings are `warn`. F and T should settle W-1 during RED/GREEN. The brief says `serde_json::Map` iterates keys in sorted order, but `preserve_order` is turned on in `--workspace` and `holler-cli` builds, so "the first extra key" must be computed explicitly rather than read off the map.

There are no `block` findings, and the rest of the plan is consistent with existing patterns. I checked each of the following:

- **Placement.** Filling `src/envelope.rs` matches `lib.rs:21, 31` and the issue. The brief rightly rules out a `conformance/envelope.rs` and reuse of `conformance::run_cases`. `run_cases` is `pub(crate)` (`conformance/mod.rs:47`), so `tests/envelope_test.rs` could not call it anyway. Its fresh-subject-per-case shape also does not fit a pure function of `(stdout, exit)`.
- **Dependency direction.** The new `serde_json` line adds no crate to the build graph, because `holler-pane` already depends on it (`holler-pane/Cargo.toml:18`). ADR-0021 section 5 (`:184-186`) allows exactly `holler-pane` and `serde_json`. `holler-cli` and `holler-hub` keep the testkit as a dev-dependency (`holler-cli/Cargo.toml:435`, `holler-hub/Cargo.toml:58`), so there is no cycle. `cargo tree -p holler-pane-testkit -e normal --depth 1` lists only `holler-pane` today, which matches AC6's baseline.
- **One classifier.** The plan calls `class_of` and `ErrorClass::exit_code` and copies neither. Rule 11 runs before rule 13, so a malformed code always gives `CodeNotKebab` and never reaches the failure branch of `class_of`. The exit set 0..=3 is the contract of ADR 0003 and ADR-0021 section 9 itself, not a table of codes.
- **Other reuse candidates rejected, correctly.** `holler_pane::reply::{PaneReply, ReplyError}` is the hub's wire reply. It is lenient (`#[serde(default)]`), carries `detail`, and has no `schema_version` (`reply.rs:14-16, 38-57`), so it cannot parse the envelope. The CLI's `output::Envelope<T>` cannot be used without a dependency cycle.
- **API feasibility at the locked version.** In `serde_json 1.0.151`, `Value` derives `Eq` (`value/mod.rs:115`), so `Envelope: Eq` compiles, and `StreamDeserializer::byte_offset` exists (`de.rs:2424`). `Map` equality ignores order with either map backend, so AC1's `data == json!(..)` holds in every build.
- **Error type pattern.** `Display` plus `std::error::Error` on `EnvelopeFault` matches `RefusalCodeError` and `InvalidCode`.
- **Test layout.** `tests/envelope_test.rs`, with sentence-style test names and builder helpers, follows `fake_pane_store_test.rs` and `pane_store_conformance_test.rs`. An in-file `#[cfg(test)]` module is the main pattern in the workspace: 39 source files use one, against 2 sibling `*_tests.rs` files.
- **Size and lints.** About 330 lines is well under `lint.sh`'s 600-line warning and 900-line failure. The brief already plans for the `clippy.toml` limits (complexity 15, 100 lines per function) and for unwrap/expect/panic being denied in test code too.
- **No other risk areas.** The plan touches no wire protocol, golden file, persistence, concurrency or secrets. `MessageNotOneLine` carries no payload, so a fault never repeats an error message.
- **CHANGELOG.** The anchor is right: after the #676 bullet, which ends at `CHANGELOG.md:89`. The style matches slice a's #638 entry (`CHANGELOG.md:42-50`).
