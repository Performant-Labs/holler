Verified and needing no action:

- **Layering and placement.** The engine is in `holler-pane` and works only through `Ports`. The verb is in `holler-cli`, and `tx_launch` is called unchanged. This is the same split as `pane launch`/`pane relaunch` (`launch.rs:68-82`) and doctor/`reconcile`.
- **Bound plumbing.** `TxOptions` comes from the caller and is handed to each `tx_launch` run (C13), which mirrors launch's and relaunch's signatures (E14, E58). The bound doc follows E10's "**Bound (I5).**" form.
- **The twins.** No leave or join helper exists in `holler-pane` (I grepped for one), and `holler-pane` cannot depend on `holler-cli` (E32). The operator decided the twins, the brief justifies them, and the follow-up issue is planned. This is a deliberate, reviewed duplication.
- **The `(session, pane_id)` comparison local to `tx_apply`.** `same_pane` is private to `tx_launch.rs`, which is not in the blast radius, and `reconcile` makes the same comparison inline (`reconcile.rs:328-336`). This is acceptable, given #1.
- **Error handling.** Exit classes go through `class_of` (`error.rs:266`), and failure output goes through `ErrorBody` (`output.rs:127-141`). So O6 needs no change to `output.rs`, to ADR-0021's decision 6 or to the test kit's envelope checker.
- **Concurrency and persistence.** The fan-out uses std scoped threads in the CLI process; `holler-pane` takes no async runtime, and nothing writes per heartbeat. There is no new persisted state and no wire or protocol change.
- **`cli-surface.txt` and ADR 0003.** Editing their own lines is the established pattern. The fixture must cover every flag, and `profile apply |` stops parsing once `NAME` is required, so the story rewrites its three lines (`cli-surface.txt:180-183`).

## Reuse expectations for Phase 7 (A-dup)

A-dup checks these against the diff. In each case the named object is what the code must extend or follow:

1. The branch contains #808, and apply's "lists the pane" check compares `(session, pane_id)` only. It does not use `HerdrPane` `==`, `contains` or `same_place`.
2. The up-front observation follows `reconcile::observe_all`: scoped `Builder` threads, each joined, with a lost thread handled. It must not use `thread::spawn` with channels, and it must add no new dependency.
3. Each row's `PaneDiff` is `diff_profile`'s row, with no `PaneDiff` built by hand.
4. The twins are exactly `detach` and a one-pane `join`: no `undo` and no profile delete. They are private, and the follow-up issue is filed.
5. Steps are classified through `class_of`, never through a local list of codes.
6. An acted failure's message carries `reconcile_step(Some(P))`, and stored strings are quoted or escaped as `show` and `launch` do it.
7. Apply's live rig is additive and follows `launch/rig.rs`'s names, and `profile_verbs/rig.rs`'s existing helpers behave as before.
8. `orchestrator-not-relaunched` is a constant in `tx_apply.rs` and appears in ADR-0021 section 9's apply row.
