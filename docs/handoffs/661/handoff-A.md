## Summary

PASS. The plan extends the object that #639 built for this purpose. It reuses the generic parts #639 marked for #661: `load_doc`/`save_doc`/`Problem` through `RegistryEntry`, `Ring`/`select`/`check_since`, `handlers::run`, `PaneStoreOptions`/`WATCH_WAIT` and `next_generation`. The one new object, `profile::store::Store`, has the same lock, save-before-commit and fail-closed shape that ADR-0021 §7 requires. The D7 comparison runs after `next_generation` under the pane lock, as ADR "Decisions taken" 2 and the fake specify. The D8 hook reads the profile registry on the blocking pool before the pane lock is taken, so no lock is nested. The plan changes no wire method, error code, golden file or ADR. Size is in line with #639, which landed as one run (12 files, +2,342 lines), so there is no size block. If F invokes the scope cap, the brief's 661a/661b split at the membership seam is clean. All eight findings are `warn`: 3-6 are for T/F during RED and GREEN, and 1 and 8 need an O/operator follow-up.

Apart from these, the plan is consistent with existing patterns. Checked and found clean:
- Layering mirrors #639 (handlers -> `run` -> store -> persist/feed).
- The profile store never takes the pane lock. The hook releases the profile lock before the pane CAS takes the pane lock, which matches the order ADR §7 sets for #665.
- `RegistryEntry` is implemented for two types: `ProfileEntry` for `load_doc`/`check`, and `ProfileEvent` for `Ring`/`select`. Both impls are needed, because the ring should not carry the logs.
- The ring holds events only.
- Load fails closed through `Problem::parse`. A `try_from` violation is a serde data error, so no file content is echoed.
- `EnvVarName`'s decode is the only env guard.
- No existing #639 test moves a pane between profiles (grep of tests/pane_*), so D7 changes no `pane/*` assertion.
- No touched file nears the 600-line warn (panes/store.rs is 352 lines, about +15).
