# Handoff-A: Phase 3 - #637 pane-control skeleton  (up-front plan review)

**Date:** 2026-10-08
**Branch:** issue-637-implementation (at 8fd92f8; base origin/main 27da2da)
**Brief reviewed:** docs/handoffs/637-brief.md   **Reuse map:** docs/handoffs/637-brief.md §Files "Reuse map" (no separate survey.md exists)   **Wireframe:** N/A (no UI surface)
**Verdict:** BLOCK

## Summary

BLOCK. The plan's overall shape is right: a new `holler-pane` domain crate, stubs per verb, `CATALOG` kept at 22 rows, and the clap structs moved out of the 701-line `cli.rs`. But six plan defects would each send T and F into an unfixable REWORK loop or into drift.

- **Missing dispatch file.** The CLI dispatches, and may exit, only in `main.rs`. That file is outside the blast radius, and `main()` is already at clippy's 100-line deny limit.
- **No home for error codes.** Decision 7 puts error codes in the frozen `vocab.rs` and names only 5. The epic names at least 8 more that belong to later stories, and #660's fixed text says the opposite.
- **Contradictory dependency rule.** Decisions 5 and 6 contradict each other about `holler-pane`'s dependencies.
- **Unconnected hub hook.** The hub hook is never called by anything, and the hub cannot even depend on `holler-pane` under the current blast radii.
- **AC 4 cannot work as written.** I checked this against the workspace's clap 4.6.6: `say --pane X TEXT` cannot parse without redesigning positionals that three out-of-radius files consume.
- **ADR 0003 left stale.** ADR 0003 (the CLI surface) is left contradicted, and #634 does not cover it.

Each fix is small and is listed under Notes for O.
