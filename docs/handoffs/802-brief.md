# [refactor(pane): HarnessPort::serve takes a ServeSpec that carries the pane's OpenCode agent (step 1 of #642 part 3)](https://github.com/Performant-Labs/holler/issues/802)

Part of epic #633. Step 1 of the agent amendment (decision 8 of the epic, from pfleet#372) **and** the fix for #695 (a wedged harness server cannot be stopped). Re-scoped 2026-10-11 by the operator; revised the same day after the architecture review of the first re-scoped run (its handoff `docs/handoffs/802/handoff-A.md` in the stopped worktree). This text is the complete statement; where an older comment disagrees, this text is the decision.

## Operator decisions (2026-10-11)

1. **How the agent is applied:** as the OpenCode server's `default_agent`, set when the server starts (not per prompt). Per prompt would need a protocol field, a hub change and a `holler-body` change; not planned.
2. **How it reaches the port:** by changing the port itself, not by an additive default-armed method for starting the server. An omitted agent becomes a compile error at every call site; every implementation is in this workspace.
3. **`ServeSpec`:** a `#[non_exhaustive]` struct holding `agent: Option<AgentKey>` today; model, effort, env names and the context ceilings join it later without another signature change. New fields of the pane's spec go into `ServeSpec`, never into new parameters.
4. **The harness server runs inside the pane's tmux session, started through the host adapter.** Operator rules: change signatures freely while in development; one source of truth; a wedged process can always be killed with extreme prejudice. `HostPort` (`run` / `stop_owned`: TERM, a shared grace, then KILL) is the one place that starts and stops a pane's processes. Consequences: `HarnessPort::serve` becomes `serve_command` (it builds the command and starts nothing); the OpenCode adapter no longer spawns `opencode serve` itself; `harness.pid` stops being a second source of truth. This absorbs #695.
5. **(review round 1, decided by the maintainer's agent under the operator's rules) The agent check after start** (#642 part 3 decision 3) stays possible: add a **required** method `HarnessPort::verify_serving(&self, port: u16, spec: &ServeSpec) -> Result<(), PaneError>` (no default: a harness that starts servers must say whether the running one honours the spec). The engine calls it **after the health wait and before `create_session`**; a refusal goes through the engine's existing rollback, which now stops the server because the server is a process of the session. #642 part 3 implements it for OpenCode; here the OpenCode implementation checks nothing beyond `Ok(())` for a spec with no agent (a spec with an agent never reaches it, because `serve_command` refuses first). #642 part 3's decisions 3, 5 and 7 are amended accordingly (done on that issue).
6. **(review round 1) The server's working directory has one source: the pane's spec** (`plan.spec.host.cwd`). `HostPort::run` gains the directory: `run(&self, name: &PaneName, cwd: &str, argv: &Argv)`; the tmux adapter passes it as `new-window -c <cwd>` (escaped like every value the adapter did not write; an empty or relative `cwd` is `usage`). The engine passes `plan.spec.host.cwd` for **both** the spec's command and the server, so a session reused after a directory change no longer starts a program in the old directory. `OpenCodeConfig.workdir` is deleted (its only reader was `serve`), and ADR-0021 section 2 fact 6 is rewritten to say the directory comes from the pane spec through `HostPort::run`. A session keeps the directory it was made with for the shell window only; nothing relies on it.
7. **(review round 1) Every refusal stays in the plan.** `serve_command` is pure, so the engine calls it **in the plan** (in `Plan::observe`, before the probe), keeps the argv there, and the act passes exactly that argv to `host.run` after `ensure_session`. An `agent-unsupported` refusal is therefore exit 3 with nothing written, no rollback and no reconcile step, like `pane-exists` and `port-in-use`.

## Acceptance (tests first)

1. `ServeSpec::default()` has `agent == None`; `with_agent(key)` holds the key; the `compile_fail,E0639` doctest passes (a struct literal and `..Default::default()` outside `holler-pane` both fail to compile).
2. **Plan order.** `serve_command` is called in the plan, before any live call; `host.run` receives exactly that argv, after `ensure_session`; an `agent-unsupported` refusal is exit 3 with nothing written, no `ensure_pane`, no rollback and no reconcile step (a test over the fakes asserting the call log and P's unchanged generation).
3. On launch and on relaunch the in-flight spec's agent reaches `serve_command` (including a relaunch whose `--agent` differs from the recorded one: the fake recorded the new agent); the act then runs, in order, `ensure_session`, the spec's command (if any), the server argv, the health wait, `verify_serving`, `create_session`/session of record, `attach_tui`.
4. **Directory.** `HostPort::run` receives `plan.spec.host.cwd` for the spec's command and for the server; a relaunch after a `cwd` change (a session made for another directory) passes the new directory (fakes assert the argument); the tmux adapter passes `-c <cwd>` and refuses an empty or relative `cwd` as `usage` (fake-tmux test), with `;` and `#` escaped.
5. `OpenCodeHarness::serve_command` with `agent: Some(_)` refuses `agent-unsupported` (nothing returned); with `None` it returns the argv `start()` built before, pinned in a test (`--port`, `--hostname 127.0.0.1`, `serve_args`, the env prefix), and starts nothing. No credential appears in any argv it returns (a test over an adapter configured with a secret-looking `Isolated` variable that is not on the adapter's own list).
6. **Health wait.** A server that never answers inside the budget ends the launch as `timeout` (`pane.launch` / `pane.relaunch`) and rolls back the session it made (rewritten AC 4b, short budget through `rig.engine`); `TxOptions.boot_poll` has a default of 150 ms.
7. **Verify.** A `verify_serving` refusal after a healthy start goes through the rollback and the server is stopped (the fake host's `stop_owned` was called and the fake server is gone); a launch with no agent calls `verify_serving` and it returns `Ok(())`.
8. `pane relaunch` of a pane whose server is running: `stop_owned` stops the server, the new one comes up on the same port, the old one is gone (fakes); a server that survives TERM and KILL fails the run loudly with no adoption (the existing test, reworded).
9. A `panes.json` written before this change still reads; a record written by `launch` after it has no `harness.pid` key (stored fixture, the hub's `pane_support/mod.rs` record).
10. The conformance suite passes for `FakeHarness` and `OpenCodeHarness` (the opt-in real test through its launcher), the new agent case holds, and the new mutant is caught.
11. `AGENT_UNSUPPORTED` is `agent-unsupported`, exit 3, listed wherever `PROMPT_UNSUPPORTED` is and in the ADR rows named in Scope 7.
12. ADR-0021 and code-doc edits as in Scope 7; `CHANGELOG.md` has an `## [Unreleased]` entry linking this issue and #695; the deleted items of Scope 3 are gone (`cargo clippy` with `dead_code` denied proves it).
