## Summary

BLOCK, on two new findings. Both sit in the exact tmux command lines the brief fixes, and neither can show up in the conformance suite or in any AC as written. AC 6d and AC 6e would pin both faulty vectors into the tests.

- **B-4.** `list-panes -s -t =NAME` is not an exact session target. `list-panes` reads `-t` as a window. Without a `:`, tmux first looks in the current session for a window with that index or name. Only then does it try the string as a session, and by then prefix matching is back on. `ps` and `stop_owned` both read this listing. So after `hj-c1r1`'s session crashes, `stop_owned(hj-c1r1)` signals the owned harness of `hj-c1r10`. That is the close-or-relaunch-after-a-crash case that conformance case 7 exists for. `=NAME:` was exact in every probe.
- **B-5.** `run` starts its program in the tmux client's working directory, not the session's. `new-window` without `-c`, from a client that is not attached, uses that client's cwd. The adapter's client inherits the cwd of the CLI or the hub, so every harness #644 launches would work wherever `holler` was started, not in `host.cwd` (`--project DIR`). `-c '#{session_path}'` fixes it, and it stays safe when the path holds `#` or `#(...)`.

Each fix is an addition: one target rule, one flag, and three AC changes. No decision is reversed. The rest of the amended plan is consistent with existing patterns. The round-1 fixes (Decisions 13 to 15, `with_kill_binary`, AC 6g to 6i, AC 11) are sound, and the probes below re-confirm the parts they rest on.

## Probe evidence (round 2)

tmux 3.7c, Linux. Each probe ran on its own private server: `tmux -S ./s -f /dev/null` from a fresh directory in the reviewer's session scratchpad (a relative socket path, so the path stays short), with `TMUX` and `TMUX_PANE` unset on every call. This session runs inside the operator's tmux, so the unset matters. Each run's exit trap killed its server and removed its directory. A process check afterwards found no probe server left. No `kill` signal was sent except signal 0 (P7). The scripts (`a641-probe.sh`, `a641-probe2.sh`, `a641-probe3.sh`) are in the scratchpad, not in the repo.

- **P1.** Only `demo-c1r1` exists. `list-panes -s -t =demo` gave `demo-c1r1 <pid>`, exit 0. `-t =demo:` gave `can't find session: demo`, exit 1. `has-session -t =demo` gave `can't find session: demo`, exit 1.
- **P2.** Only `alpha-c1r10` exists. `list-panes -s -t =alpha-c1r1` gave `alpha-c1r10 <pid>`, exit 0. `-t =alpha-c1r1:` gave `can't find session: alpha-c1r1`, exit 1.
- **P3.** Session `1` exists, and the newest session `zz` has windows 0 and 1. `list-panes -s -t =1` gave `zz`'s two panes, exit 0. `-t =1:` gave session `1`'s pane.
- **P4.** There is no session `ghost-c1r1`, and `zz` has a window named `ghost-c1r1`. `list-panes -s -t =ghost-c1r1` gave `zz`'s three panes, exit 0. `-t =ghost-c1r1:` gave `can't find session`, exit 1.
- **Q1 to Q4.** The shadows of P2, P3 and P4 were set up together. For all three names, `has-session -t =NAME`, `new-window -t =NAME:` and `list-panes -s -t =NAME:` each gave `can't find session`, exit 1. `list-panes -s -t =NAME` without the colon listed `alpha-c1r10` for the first name and `zz` for the other two.
- **Q5.** `list-panes -F '[#{pane_pid} #{pane_dead} #{@holler-pid}]'` gave `[<pid> 0 ]` for an untagged pane and `[<pid> 0 <pid>]` for one tagged with `set-option -w -t @N @holler-pid <pid> \; set-option -w -t @N remain-on-exit off`.
- **P5.** The session was made with `-c $D/A`, and the client's cwd was `$D`. `new-window ... -- env -- sleep 30` with no `-c` gave a process whose cwd was `$D`. With `-c '#{session_path}'` the cwd was `$D/A`, and `#{session_path}` read `$D/A`. Other sessions existed at the time, including the current one at `$D/B`, so the expansion is against the target session.
- **P6.** Sessions were made with `-c "$D/p##S"` and `-c "$D/##(touch $D/ran2)"`. Each `session_path` was the literal path. `new-window -c '#{session_path}'` gave a process whose cwd was that literal path, and `ran2` was never created.
- **P7.** `/usr/bin/kill -s 0 -- -<pgid of a reaped process>` printed `/usr/bin/kill: (-<pgid>): No such process`, exit 1 (procps-ng 4.0.4).
- **R1.** `new-session` was run with `HLR_PROBE_VAR=from-first-client` on the client that started the server. A pane started later, by a client without the variable, printed `from-first-client`.
- **R2.** With global `remain-on-exit on`, `new-window ... -- env -- true` was followed after 0.5 s by the tag invocation, exit 0. The listing kept the window as `[<pid> 1 <pid>]`, and `kill -0 <pid>` found no process.
