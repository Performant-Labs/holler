**The plan extends the right objects:**

- the port itself, not twins: `HarnessEndpoint` in place of `port: u16`, which follows #802 decision 2;
- `HarnessInfo`, in the optional-field form;
- the facts about a kind as methods of `HarnessKind` (decision 25);
- the one `harness` of `Ports`, behind a router;
- a new adapter crate that only `holler-cli` depends on (ADR section 5);
- the test kit's fake and conformance pattern;
- the engines, rather than a parallel launcher.

**It respects the choke point.** A Claude pane gets no CLI-side `say`, and the acceptance step that needs #839 and #850 is written down rather than worked around. The operator's abort decision is recorded in section 15, in "Decisions taken" 22, and in the research note.

**Why no block.** Each finding has a fix that keeps an existing contract or follows an existing pattern, and none needs an operator decision. The top four are corrections to section 15's text. T pins them in RED, and F records them in section 15 "as built" (the brief already gives F "as built" facts to add). The PR body lists them as edits to the amendment.

The four that matter most:

- **W1. The switch contract regresses.** Section 15 skips `list_sessions`, and `process_command` picks `--session-id` whenever no transcript exists. Together they make a Claude-pane `switch` to any well-formed unknown id start an empty conversation and record it. Today a switch to an unknown target is `session-not-found`.
- **W2. `doctor --fix` would become a relaunch** with no idle gate. That drops a running turn, which `reset` and `switch` refuse to do. Reconcile's own record write would then conflict with the relaunch's. Reconcile's stated contract and ADR §8 are not amended to match.
- **W3. Reconcile's per-pane chain is undefined for a single process**, and "doctor is clean" is an acceptance line.
- **W5. The router's home is unstated.** A router built in the wiring and another in the test kit would be two copies of the routing rule, because the test kit is a dev-dependency of `holler-cli`.

### Details

**W1. The switch target.**

- **Today's contract.** A switch's plan checks that the pane's own server lists the target (`check_listed`, `tx_switch.rs:331-339`). An unknown id is the closed `session-not-found`, with nothing moved (ADR §8:530-531).
- **What section 15 does to it.** For a SingleProcess pane, item 6 skips `list_sessions`. Item 5 then decides between `--resume` and `--session-id` from whether the transcript exists. The spike verified that a second `--session-id <id>` for a never-prompted id "is accepted and holds that id" (`claude-code-pane-spike.md:91`).
- **The result.** A switch to an id that exists nowhere succeeds: the process starts a fresh conversation under that id, and the record names it as the session of record.
- **The fix.** The spike recommended `process_command(name, spec, SessionChoice)` (`claude-code-pane-spike.md:300-303`); the amendment simplified it to `session`. The choice carries the switch's intent: a resume-only choice refuses a target with no transcript, in the plan, before anything is stopped.
  - Keep the existence check as it is: one file's existence, never its contents.
  - The record write and the rest of the switch stay as they are.

**W2 and W4. The relaunch, and reconcile's repair.**

- **The relaunch.** `tx_launch::relaunch` is the engine `pane relaunch` and `profile apply` already share. Its rules (E0) are "the engine's first step ..., so every caller is held to them" (`tx_launch.rs:25-29`).
  - A relaunch with W1's choice serves switch, reset, interrupt and the repair with one stop, run, wait, locate and record sequence.
  - A second copy in `tx_switch`, or inside reconcile, is the duplication Phase 7 rejects.
- **Reconcile's repair.**
  - **One way in.** Reconcile is the observation engine that `tx_launch`, `tx_switch` and `tx_apply` depend on (`shown_differs`). It should not import `tx_launch`. The `edit_spec` act (`ProfileScope::edit_spec(..., act)`) is the codebase's form for "the caller supplies the live step", and the alternative is `pane doctor` running the relaunch after the pass.
  - **The idle gate.** It follows `check_idle`, so an unattended repair never drops a running turn.
  - **The record step.** The chain's own write must be skipped after a relaunch repair (the engine stored the record and its observation). Otherwise a successful `--fix` reports `observe-failed: another writer changed the record`.

**W3. The chain for a SingleProcess pane.**

- **The calls.** The calls in W3's fix all go through `HarnessEndpoint::Process`, so the chain needs no new port method.
- **What a pass reports.** `server-down` is reused for "no `agents --json` entry for the recorded pid" (item 13). `pane-waiting` comes from `session_activity` (`waiting` and its reason). A person's `/clear` shows as `shown_session` differing from the session of record, which is the one SingleProcess mismatch.
- **What a pass skips.** It leaves out the rules that need a server's list: `session-of-record-missing`, `tui-foreign-session`, `stray-session`, and `server-wedged`, which is a list that times out.
- **What T pins.** Doctor is clean for a healthy, idle Claude pane, which is the acceptance line.

**W5. The router.**

- **Where it can live.** `holler-cli`'s manifest lists `holler-pane-testkit` under `[dev-dependencies]`, so production wiring cannot use a test-kit type. The test kit depends only on `holler-pane`, so it cannot use a wiring type. A router that both use can only live in `holler-pane`.
- **The precedent.** `tx_launch::wait_healthy` is already shared this way, by the engine, the conformance suite and the adapter's real tests.
- **The pins.** Running both conformance suites over the router pins every route at once. The existing `Wired` forwarding test then needs only the four new methods added to its `Recording` and its `call_every_method`.

**W8. The socket file.**

- **Why the writer matters.** The hook's command is shell text that Claude Code runs. If the adapter builds that text with a path in it, a path with a quote or a `$` becomes code. Passing the path in an environment variable, and quoting it in fixed text, removes that.
- **Keying, and the pid.** Keying by pid matches the endpoint's identity. The spike also notes that a SIGKILLed process leaves files behind (`claude-code-pane-spike.md:101-104`), so a reader must check the file against the live `agents --json` entry before using it.
