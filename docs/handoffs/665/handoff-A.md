## Summary

PASS, with no block and six warns.

The plan extends the right objects in the right layers:

- **Rename** is a store-level transaction on the hub, under the lock order ADR-0021 section 7 already reserves for `profile/rename`. It is decoded through the shared handler pipeline (`panes::handlers::run`).
- **The verbs** run CLI-side over the existing ports, with no port method, no `Ports` field and no wrapper change.
- **The file format** lives in the CLI, as ADR-0021 section 5 requires (`holler-pane` "knows no file format", `import/files.rs:3`). It is validated by the crate's own typed guards through `decode_params` and `GridPos::parse`.
- **The finding** is one kind in `findings.rs`, computed by `diff_profile`, the comparison `profile show` already uses, in its own child module of `reconcile`.

**The Evidence is accurate.** I checked every quoted source line of E3 to E72 and E77 against `bda1069` with a script: 1,599 lines, none different.

The warns change no design decision. They pin details that the brief leaves to F, or that it states wrongly:

1. **Two test files fail CI** once the verbs and the new conformance cases land. Neither is in the Blast radius.
2. **D2's transaction shape:** the owned pane handle, ADR section 7's wording, the order of the checks, the store twins and the operating limits.
3. **D3's port doc** is false for `ProfileState` on a hub that has member panes.
4. **D7's key order** relies on a `serde_json` feature that holler-cli gets only by accident.
5. **D8 and D9 classify file errors** differently from the `pane import` precedent.
6. **Placement of the large new test suites and conformance cases** is not named.

## Reuse expectations for Phase 7 (A-dup)

A-dup checks the diff against these. Any near-copy of the named object is a rejection.

1. **Membership** is `holler_pane::profile_diff::is_member` everywhere: the hub transaction, the drift step and the doctor rig. Nothing compares names as strings.
2. **The hub write rules are reused.**
   - Generations come from `holler_pane::next_generation`, and log entries from `profile::store::log_entry`.
   - Both entries come from `ProfileEntry::next`, so OLD's log and NEW's log each go on.
   - The one stamp is `entry::stamp` folded over OLD's entry and NEW's previous entry, so `at` never decreases in either log.
   - `entry.rs` changes only if a constructor is truly missing.
3. **The twins are extended in place.** `save`, `commit` and `entries_with` take a slice of changes in both stores, under the same names (warn 2c). The restore is `save` of the committed table, and every fault is logged through `panes::log_fault`.
4. **`profile/rename.rs` follows the handler pattern.** It decodes `ProfileRenameParams` through `panes::handlers::run`, like the other `profile/*` handlers (`profile/handlers.rs:41-55`), with no second decode or blocking pipeline.
5. **One `Store::rename`** serves the record half (the port) and the transaction (warn 3).
6. **The fake's rename** runs in one `feed.write` and uses the fake's own `entry`, `record` and `next_generation`. It is not a second copy of `put` or `remove`.
7. **The conformance cases reuse the suite's helpers:** `Shown`, `Step`, `expect_code`, `expect_eq`, `succeeds`, `sample_profile`, and the names `ALPHA`, `ALPHA_SHOUTED` and `BETA`.
8. **The CLI verbs reuse what create, show and output already provide.**
   - Import stores through `create::insert_profile`, the one create write and race mapping. It builds the record as `Profile { panes, ..profile_from_panes(&name, &[]) }`, as `copy_of` does, never by hand.
   - `profile-exists` comes from create's `taken`, made `pub(crate)`, not spelled again.
   - Specs decode through `holler_pane::reply::decode_params`, and grids through `GridPos::parse`.
   - `--out` is written by `holler_proto::atomic_file::write_atomic` at 0600.
   - Paths print through `show::text`, the actor is a `const ACTOR` passed to `Actor::parse`, and the result goes through `output::emit`.
   - The shared document code lives in `export.rs` and is reached as `super::export::...`. The frozen `profile/mod.rs` gets only its doc line, as #676 changed one.
9. **Drift reuses the existing comparison and finding helpers.**
   - The comparison is `diff_profile` itself, the finding `Finding::about`, the quoting `findings::quoted` and the field paths `SpecField::as_str`. A failed read uses `super::failed_message`.
   - `reconcile.rs` gets one `mod drift;` line, one call, and one line in the module docs naming the new `profile_store.list` read.
   - A read run after the fan-out, not in parallel with it, is acceptable: `resolve` already reads the pane store the same way.
10. **The doctor rig** builds `profiles_of` with `profile_from_panes` over the stored records. No new snapshot helper.
11. **D6 holds:** no port method, no `Ports` field or literal, and no `wiring/bind.rs` edit.
