## Summary

PASS. The plan extends the objects it should and adds no parallel path:

- **Crate and dependency.** It fills the empty `holler-pane-testkit` crate that #637 registered. Its one normal dependency is `holler-pane`, which ADR-0021 §5 allows (lines 184-186). The hub and the CLI already dev-depend on the crate, so no other manifest changes and no cycle forms.
- **Reused, not rewritten.** It implements the frozen `PaneStore` trait. It calls `next_generation` for every CAS, returns only the closed `PaneError` variants, and identifies profiles by `ProfileName::slug` (ADR-0021 §1).
- **New objects, each justified in writing.** The generic `FaultSwitch` and the generic feed are the only ones in the crate. The hub's `feed.rs` and `store.rs` are `pub(crate)` in a crate the testkit must not depend on. `MemPaneStore` is the accepted near-duplicate; its conclusion holds, but its stated reason does not (W-8).

I traced the 19 conformance cases against the hub's `PaneState` on `issue-639-implementation` (9289d30). Cases 1-18 hold. Case 19 fails until #661 adds the membership check, as the brief says.

All 12 findings are `warn`, so none blocks T:

### Checked and consistent

- **Dependency rule.** ADR-0021:184-186 allows this dependency, and AC 1's `cargo tree` check enforces it. The consumers' dev-dependencies already exist (`holler-hub/Cargo.toml:55-58`, `holler-cli/Cargo.toml:432-435`), so no manifest outside the crate changes. Tests need nothing beyond `std`, the crate and `holler-pane`, so the plan to add no `[dev-dependencies]` holds.
- **Port semantics against the real store.** On the 0639 branch, `Store::cas_put` and `Store::delete` (`store.rs:165-201`) and `feed::check_since` and `select` (`feed.rs:86-120`) match the fake's rules:
  - the stored record is the submitted one with only its generation replaced;
  - a missing record is checked before the generation;
  - a cursor ahead of the head is `usage`;
  - an error ends the stream.
- **ADRs.** No ADR is contradicted. Brief decisions 4 to 6 model hub behaviours the port leaves open. The split keeps ADR-0021 §2's "#638 ships the suites", so no ADR edit is needed.
- **Layering inside the crate.** The suites are generic over the trait and do not name the fake. The fakes do not name the suites. The mutants live in `tests/`. `fixture.rs` is shared by both. This matches the brief's "no flat re-exports". `holler-pane`'s own `lib.rs` re-exports flat, but that would make every later slice edit this crate's `lib.rs`, which the split avoids.
- **Module root.** The `conformance/mod.rs` root follows the epic's operator-accepted precedent (#670 W-10; `holler-hub/src/panes/mod.rs:42-43`), and #681 to #684 already name it. No change.
- **Size.** About 1,550 lines in 6 modules, within one run's limit. The largest file is planned at about 400 lines, and the lint warns at 600.
