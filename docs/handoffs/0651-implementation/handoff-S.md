## Honest limits (all recorded upstream of this audit; none silent)

1. **Unknown-never-stale is in-process (criterion 4).** Across invocations the guarantee is "stale pane tokens expire within 120 s", not "unknown actively shown": a hub that dies between event hooks leaves the last facts on screen up to the TTL with no `unknown` label, and a degraded one-shot refresh reports zero panes. Accepted by the operator (journaled) as the one-shot-binary reality; the closing fix — a `pane/watch` loop or a persisted last-reported set — is epic follow-up material, not this story's contract. **This is the one place the shipped behavior is weaker than the issue's literal sentence, and the operator merges it knowingly.**
2. **Workspace `profile` tokens carry no TTL by design (spike §4)** and a degraded refresh sends no workspace reports — so a workspace's profile token persists while the hub is down. Static fact; recorded by F (finding 4) and T-green.
3. **Actions cannot yet act (criterion 2 note).** Bare `["holler","pane",<verb>]` carries no pane operand, `resolve_action_pane` has no production caller, and the CLI verbs themselves are unwired until #649 (`Wiring::connect` still hands out `Unwired`). The actions are manifest placeholders exactly as the brief pinned; the wiring is #649's. Also the natural moment to pin the 4th SYNC case (`at > 0`, no session of record → `-`).
4. **Token values are sent verbatim** (`host.cwd`, session names); whether Herdr's sidebar escapes them is unverified (A-dup warn 2). If it does not, apply the CLI's `text_value` rule in a follow-up.
5. **A-dup's warn 1 doc line** (the "second consumer → move `report_metadata` into the adapter crate" escalation note in `src/herdr.rs`) was suggested, not demanded, and is not present — non-blocking; fold it into the follow-up that extracts the client.
