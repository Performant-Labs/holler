# ADR 0003 — CLI surface of the single binary; one version

**Status:** accepted (`hub token delete`/`revoke` clarified 2026-09-26; the CLI table below carries the `--server URL` remote form epic #506/ADR 0020 added 2026-09-27, rewritten into this table rather than appended as a note — see below)
**Issue:** [#4](https://github.com/Performant-Labs/holler/issues/4)
**Date:** 2026-09-07
**Depends on:** [ADR 0001](ADR-0001.md); the reachability of the hub-only verbs in this table now also depends on [ADR 0020](ADR-0020.md)
**Supersedes:** server ADR-0014 and client ADR-0003 (versioning); the CLI tables in holler-server#1, #27, and holler-client#22
**Clarified by:** [#454](https://github.com/Performant-Labs/holler/issues/454) (2026-09-26) — `hub token delete` and `hub token revoke` are no longer one store operation. `revoke` keeps the token's record (and so its label); `delete` removes an unused or revoked token's record, which frees its label, and refuses a bound token with exit 3. Before #454 both spellings revoked and kept the record.

## Decision

This ADR fixes the **complete CLI surface** and the **versioning policy** of the single `holler` binary. Later stories implement exactly this surface — the same verbs, the same flags, the same exit codes — so nobody adds a fourth spelling of `status`. The workspace clap tree (the Cargo skeleton story) must match this table verb-for-verb.

### CLI (normative)

Implement exactly this. **No aliases unless listed.** The machine-readable form of this table is `crates/holler-cli/tests/fixtures/cli-surface.txt` (every implemented verb and flag; asserted equal to the clap tree) plus `cli-surface.pending.txt` (verbs below that no story has implemented yet — asserted **not** to parse until their story moves them over).

### Rules

- `revoke` and `delete` are **two operations** ([#454](https://github.com/Performant-Labs/holler/issues/454)). `revoke` cuts a token's access now (an unused secret is invalidated; a bound body's credential is refused and its live socket closed) and **keeps the record**, so `list` still shows who was cut off and the record still holds its label. `delete` **removes** an `unused` or `revoked` token's record, which frees its label for a new `mint`; on a `bound` token it is a fail-closed refusal (exit 3) that names the `revoke` to run first, and nothing changes. A `mint` over a held label exits 3 and names the token that holds it and the commands that free it.
- `say`, `interrupt`, `answer`, `wait`, `roster`, `hub status`, and `hub query` are **hub-only** operations: they reach a live `hub serve`, either over its local control socket (the default, no `--server`) or, since ADR 0020 (epic #506), over the hub's WebSocket circuit from another machine (`--server URL`) — the remote form authenticates with the credential of a body the calling machine has already joined to that hub, not a separate admin credential. `say`/`interrupt`/`answer`/`wait`/`roster` are **top-level** because they are the daily verbs; `hub status`/`hub query` stay namespaced under `hub` because ADR 0001 already claimed `status`/`query` as per-role verbs. The busy-turn policy (`--queue`, `interrupt … TEXT`), `answer`, and `wait` are specified in holler#150, #151 and #142 respectively.
- `--json` is a **global** flag: it parses after any leaf (`hub token mint --label x --json`), not only where a verb "notes" it.
- `SESSION` is `<label>/<session>` (ADR 0005). A **bare `<session>`** is accepted when exactly one roster row matches; otherwise **exit 2** with the candidates listed, one per line.
- `roster --prefix PREFIX` lists every row named exactly `PREFIX` or nested under it (`PREFIX/…`) — ADR 0005 §4's transitive prefix match (e.g. `--prefix io` matches `io` and every `io/<session>`). `roster --all` includes `gone` rows (bodies that dropped off) in the listing, which the default (live-only: `connected` + `reconnecting`) omits; the two flags compose (`--all --prefix io` lists every row under `io`, `gone` included).
- `TARGET` resolution order for remote `query`: exact `label/session` → `label` → `client id` → `token id`. **Ambiguity is an error, never a guess.**
- **Exit codes:** `0` ok; `1` runtime failure (unreachable hub, wire error, interrupted turn); `2` usage/ambiguity; `3` fail-closed policy refusal (e.g. non-loopback bind, invalid `--debug`).
- `--json` prints **exactly one JSON object** to stdout; **all diagnostics go to stderr.**
- `-V`/`--version` and `--help` exit `0`; a **bare `holler`**, `holler hub`, `holler body`, or an **unknown subcommand** prints usage to stderr and exits `2`.

### Versioning

- **One version**, in the workspace `Cargo.toml` `[workspace.package] version`; member crates use `version.workspace = true`.
- **SemVer from 0.1.0.** Standard pre-1.0 behaviour — **breaking changes bump MINOR while MAJOR is 0**. This **deliberately reverses ADR-0014's opt-out**, because there is no external library consumer.
- **"Breaking"** = the CLI surface, the `--json` shape, the on-disk formats (token store, credential file, session config), and the wire protocol version. **Additive = MINOR. Fixes = PATCH.**
- **Bumps happen at release points only** (Releasing story).

## Consequences

- The clap tree in the Cargo workspace skeleton is the implementation of this table; `cli_surface_test.rs` asserts the fixture and the clap tree name the same leaf verbs, every fixture line parses, and every pending line does not; `cli_invocation_test.rs` asserts every unlisted spelling is rejected; `docs_cli_test.rs` parses every `holler …` shown in `README.md` and `docs/**`.
- `hub` and `body` each expose `status`/`caps`/`support`/`query` **under the role namespace**, resolving ADR 0001's verb-collision argument; `say`/`interrupt`/`roster` are the only top-level verbs. `hub status`/`hub query` (and every top-level hub-only verb) resolve which hub to reach the same way regardless of where the caller runs: local by default, or the hub named by `--server URL` (ADR 0020) — the role namespace this decision fixes and the local/remote reachability ADR 0020 later added are independent axes.
- A single workspace version means `holler --version`, the `--json` document, and the on-disk formats all move together (ADR 0002's "one released artifact, one version").

## Not decided here

- **Addressing** — `SESSION`/`TARGET` expand under ADR 0005 (`<label>/<session>`).
- **Wire** — the `--json` document shapes follow ADR 0004 (protocol v2).
- **Roster** — the `roster` output shape and the periodic `session/presence` it reflects are the Roster story.
