# ADR 0003 — CLI surface of the single binary; one version

**Status:** accepted
**Issue:** [#4](https://github.com/Performant-Labs/holler/issues/4)
**Date:** 2026-09-07
**Depends on:** [ADR 0001](ADR-0001.md)
**Supersedes:** server ADR-0014 and client ADR-0003 (versioning); the CLI tables in holler-server#1, #27, and holler-client#22

## Decision

This ADR fixes the **complete CLI surface** and the **versioning policy** of the single `holler` binary. Later stories implement exactly this surface — the same verbs, the same flags, the same exit codes — so nobody adds a fourth spelling of `status`. The workspace clap tree (the Cargo skeleton story) must match this table verb-for-verb.

### CLI (normative)

Implement exactly this. **No aliases unless listed.**

```text
holler --version | -V                       prints `holler X.Y.Z` (workspace version)
holler --help
global flags on every subcommand:  --debug none|quiet|noisy   --log-format text|json   --json (where noted)

holler hub serve [--listen HOST:PORT]... [--advertise HOST[:PORT]]
holler hub token mint --label LABEL [--ttl 24h] [--json]
holler hub token list [--json]
holler hub token delete ID            (aliases: rm, remove) — unused token: invalidate the secret
holler hub token revoke ID            (alias of delete for a BOUND token) — cut the body's access now, keep the record
holler hub token ping ID [--json]
holler hub status [--json]
holler hub caps [--json]
holler hub support FEATURE [--json]
holler hub query CMD [ARGS...] [--json]               (local: this hub process)
holler hub query TARGET CMD [ARGS...] [--json]        (remote: TARGET = token id | client id | label | label/session)
holler roster [--json]
holler say SESSION TEXT [--timeout 600s] [--json]
holler interrupt SESSION

holler body join --server URL --token ID:SECRET
holler body run [--config PATH]
holler body detach
holler body status [--json]
holler body caps [--json]
holler body support FEATURE [--json]
holler body query CMD [ARGS...] [--json]
holler body attach sessions [--endpoint URL]
holler body attach init [--endpoint URL] [--session ID] [--name NAME] [--out PATH] [--force]
```

### Rules

- `delete` and `revoke` are the **same operation on the store**. `revoke` exists because "delete" misdescribes cutting a live machine's access while keeping its record. Either spelling works on either token state; `list` shows `revoked` rows until `token purge` (**not in v1**).
- `say`, `interrupt`, and `roster` are **hub-only** operations — they reach a live `hub serve` over its control socket. They are **top-level** because they are the daily verbs. Everything else is namespaced by role.
- `SESSION` is `<label>/<session>` (ADR 0005). A **bare `<session>`** is accepted when exactly one roster row matches; otherwise **exit 2** with the candidates listed, one per line.
- `TARGET` resolution order for remote `query`: exact `label/session` → `label` → `client id` → `token id`. **Ambiguity is an error, never a guess.**
- **Exit codes:** `0` ok; `1` runtime failure (unreachable hub, wire error, interrupted turn); `2` usage/ambiguity; `3` fail-closed policy refusal (e.g. non-loopback bind, invalid `--debug`).
- `--json` prints **exactly one JSON object** to stdout; **all diagnostics go to stderr.**
- `-V`/`--version` and `--help` exit `0`; a **bare `holler`**, `holler hub`, `holler body`, or an **unknown subcommand** prints usage to stderr and exits `2`.

### Versioning

- **One version**, in the workspace `Cargo.toml` `[workspace.package] version`; member crates use `version.workspace = true`.
- **SemVer from 0.1.0.** Standard pre-1.0 behaviour — **breaking changes bump MINOR while MAJOR is 0**. This **deliberately reverses ADR-0014's opt-out**, because there is no external library consumer.
- **"Breaking"** = the CLI surface, the `--json` shape, the on-disk formats (token store, credential file, session config), and the wire protocol version. **Additive = MINOR. Fixes = PATCH.**
- **Bumps happen at release points only** (Releasing story).

## Consequences

- The clap tree in the Cargo workspace skeleton is the implementation of this table; `cli_invocation_test.rs` asserts every listed subcommand parses and every unlisted one is rejected (verified in the skeleton story, not here).
- `hub` and `body` each expose `status`/`caps`/`support`/`query` **under the role namespace**, resolving ADR 0001's verb-collision argument; `say`/`interrupt`/`roster` are the only top-level verbs.
- A single workspace version means `holler --version`, the `--json` document, and the on-disk formats all move together (ADR 0002's "one released artifact, one version").

## Not decided here

- **Addressing** — `SESSION`/`TARGET` expand under ADR 0005 (`<label>/<session>`).
- **Wire** — the `--json` document shapes follow ADR 0004 (protocol v2).
- **Roster** — the `roster` output shape and the periodic `session/presence` it reflects are the Roster story.
