# ADR 0001 — One binary, two roles: hub and body

**Status:** accepted
**Issue:** [#2](https://github.com/Performant-Labs/holler/issues/2)
**Date:** 2026-09-07
**Supersedes:** `holler-server` ADR 0001 (talk circuit), `holler-server` ADR 0002 (remote body is holler-client, not Herdr), `holler-client` ADR 0001 (speak v1, answer query locally)
**Executes:** [holler-client#129](https://github.com/Performant-Labs/holler-client/issues/129)

## Decision

`holler` is a **single executable** with two roles:

- `holler hub …` runs the **circuit**: the listener, the join tokens, the roster, and the talk log.
- `holler body …` **joins a hub** and drives the local coding-agent sessions.

A machine may run **either or both**. The old `holler-server` / `holler` binary split is retired; there is one artifact that is the hub and the body depending on how it is started.

## Why

1. **The split hard-coded "hub machine vs body machine" at install time.** A machine that both hosts the circuit *and* offers its own sessions is a normal topology — you want the home machine to be an animal in the herd, too. With two binaries that choice is baked in at install; with one binary it is a **runtime choice** (`holler hub` or `holler body` on the same box).

2. **The old pair collided on the operator surface.** `status` / `caps` / `support` / `query` existed on **both** binaries with the **same spelling and different meanings** (the server's `status` is "this hub as a peer"; the client's `status` is "this body as a peer"). Namespacing the verbs — `hub status` vs `body status` — removes the collision without inventing new words.

3. **One artifact, one version, one install line, one release matrix.** A single binary means a single `holler` to build, a single version number, a single install line, and a single release matrix to test. Two binaries meant four corners of that matrix and a release that had to keep them in lockstep.

## Consequences

- **Crates.** The workspace is split so the roles stay separable but ship as one binary:
  - `holler-proto` — the wire (protocol v2, [ADR 0004](../ADR-0004.md)).
  - `holler-hub` — the hub role, as a library (listener, tokens, roster, talk log).
  - `holler-body` — the body role, as a library (join, local sessions, adapters).
  - `holler-cli` — the `holler` **bin**; it is the only crate that is released.
- **State dir.** `HOLLER_STATE_DIR` (default `~/.holler`) holds a `hub/` subdirectory and a `body/` subdirectory so both roles coexist on one machine without trampling each other.
- **Attack surface.** A body-only machine carries **hub code it never executes**. That is a recorded, accepted trade-off of one artifact: the hub's listener and token-minting paths are present in the binary but unreachable without running `holler hub`. **Secrets live in the state dir, not the binary**, so the shipped artifact carries no credentials. Recorded, not blocking.
- **Naming.** The crate name `holler` is taken on crates.io by an unrelated project. The **binary is still `holler`** — declared as `[[bin]] name = "holler"` inside the package `holler-cli`. **Nothing is published to crates.io in v1.**

## Not decided here

- **CLI verbs** — `ADR 0003` (the `hub` / `body` namespace and the top-level `say` / `interrupt` / `roster`).
- **Wire** — `ADR 0004` (Holler protocol v2, JSON-RPC 2.0 over WebSocket text frames).
- **Naming** — `ADR 0005` (the session/label scheme, e.g. `io/alpha`).

## Superseded

This ADR retires the three-role story of the split repos:

- `holler-server` **ADR 0001** (*Talk circuit, not a multiplexer*) — the circuit definition now lives in the [project brief (#1)](https://github.com/Performant-Labs/holler/issues/1) and in the protocol ADR; the "one binary" framing here replaces its hub/client split.
- `holler-server` **ADR 0002** (*Remote body is holler-client, not Herdr*) — the "far box never runs Herdr" decision survives, but it is now a *role* (`holler body`) of the single binary rather than a separate `holler-client` repo.
- `holler-client` **ADR 0001** (*Speak Holler protocol v1; answer query locally*) — the "answer `query` from local probes, never from a model" rule survives under the `body` role; the v1 envelope is retired (protocol v2 is [ADR 0004](../ADR-0004.md)).
