# ADR 0013 — Body protocol is ACP v2 via the official Rust SDK (2.1.0)

**Status:** accepted
**Issue:** [#14](https://github.com/Performant-Labs/holler/issues/14)
**Date:** 2026-09-09
**Depends on:** [ADR 0004](ADR-0004.md)
**Supersedes:** `holler-server` ADR-0008 (v1 body is OpenCode via ACP), ADR-0012 (body protocol is ACP v1), ADR-0013 (Rust, because we want the official ACP SDK)

## Decision

The body hop speaks **Agent Client Protocol v2**, via the official Rust SDK crate `agent-client-protocol`, pinned to **2.1.0**. `holler-server`'s original three ADRs each pinned a piece of this (OpenCode as the default command, ACP v1 as the version, Rust as the language for the sake of the official SDK); this repo folds them into one decision because in the rearchitected system they are one fact, not three — the body hop's shape (ADR 0004) already assumes ACP is the protocol underneath it, so pinning the version and the SDK is this ADR's whole job.

1. **Version: ACP v2, not v1.** ACP v1 was the only stable release when `holler-server` made its original pin; v2 has since stabilized and is used here because it adds a state the v1 gate never had a name for: `requires_action`. On Holler's wire (ADR 0004), that ACP state is the reason the session's A2A-flavored state gains `input-required` alongside `idle`/`working` — a session paused waiting on a permission or elicitation decision, not merely "still running." Holler's `input-required` is the wire name; ACP's `requires_action` is the underlying agent-side state it is derived from.
2. **SDK: the crate, not a hand-rolled client.** `crates/holler-body` depends on `agent-client-protocol = "2.1.0"` (workspace-pinned in the root `Cargo.toml`, feature `unstable_protocol_v2`) — the same crate the spec's own org (Zed/JetBrains-governed) publishes, not a community reimplementation. The driver maps `session/prompt`/`session/update`/`session/cancel` 1:1 onto this crate's types, matching ADR 0004's "ACP behind the wire, byte-identical objects out" framing.
3. **Rust rationale is kept, restated for the single binary.** ADR-0013's original argument — implement in Rust *because* the official ACP SDK is Rust, not because of performance — still holds and is not re-litigated: Holler is not CPU-bound, and the reason for the language choice is drift risk against the spec's own schema, which the official SDK owns and a community Go/JS port would not.
4. **No harness is compiled in because of this pin.** This ADR fixes the *protocol* a body speaks to whatever it drives; it says nothing about which harnesses exist — that stays config, per [ADR 0012](ADR-0012.md). A harness that does not natively speak ACP v2 needs an out-of-tree adapter in front of it; Holler's own dependency is on the protocol and the SDK, never on any one harness's CLI.

## Why

Staying on the SDK the protocol's own maintainers publish is the same argument `holler-server` ADR-0013 already made: tracking spec drift is the SDK owner's problem when you depend on their crate, and becomes your problem the moment you hand-roll a client or depend on an unofficial port. Moving from v1 to v2 is not a change of that argument, only of which stable release it currently points at — v2 is the version that is now stable and that carries `requires_action`, which several other decisions in this rewrite (the roster's `input-required` state, `answer SESSION CHOICE`, ADR 0009's interrupt semantics distinguishing a busy turn from a session waiting on input) depend on having a name for.

## Consequences

- `crates/holler-body/Cargo.toml` depends on `agent-client-protocol = { workspace = true }`, pinned in the workspace root to `2.1.0` with `features = ["unstable_protocol_v2"]`; bumping that pin is a workspace-wide, single-line change, matching ADR 0003's "one version" policy for everything else in the binary.
- The A2A↔ACP `stopReason` mapping and the `input-required` state (ADR 0004, `docs/protocol/v2.md` §6) are the observable surface of this pin; a reader who wants the mapping table looks there, not here.
- New harnesses still cost zero Holler releases (ADR 0012); this ADR only fixes what protocol version the subprocess or attached endpoint must speak underneath whatever adapter fronts it.

## Not decided here

- Config shape for a harness (spawn vs attach, command vs endpoint) — [ADR 0012](ADR-0012.md).
- The wire between hub and body, and the A2A object model it reuses — [ADR 0004](ADR-0004.md).
- Attach mode's specific ownership rules for a session that is not spawned by this process — [ADR 0014](ADR-0014.md).
