# ADR 0008 — Tokens hashed at rest with a pepper; TLS is the proxy's job

**Status:** accepted (§1–2 narrowed 2026-09-11 — see below)
**Issue:** [#9](https://github.com/Performant-Labs/holler/issues/9)
**Date:** 2026-09-09
**Depends on:** [ADR 0006](ADR-0006.md), [ADR 0007](ADR-0007.md)
**Supersedes:** `holler-server` ADR-0010 (tokens hashed at rest; TLS on the wire — the Tailscale-is-not-encryption argument is kept, restated here as underlay/proxy framing)
**Narrowed by:** [ADR 0018](ADR-0018.md) (issues [#322](https://github.com/Performant-Labs/holler/issues/322)/[#323](https://github.com/Performant-Labs/holler/issues/323), 2026-09-11) — a simplification, not an extension: §1–3's "both [the join secret and the credential] are `HMAC-SHA-256(pepper, secret)`" now applies to the join secret only, because the credential it used to also cover no longer exists (the hub stores a **public key** for a bound token instead). §3's pepper mechanics, §4 (TLS is the proxy's job), and §5 (an underlay is never identity) are unaffected and still stand exactly as written.

## Decision

Holler does not implement its own cipher, and confidentiality on the wire is **not this ADR's job** — it is [ADR 0006](ADR-0006.md)'s, entirely delegated to whatever TLS-terminating proxy sits in front of the hub's loopback listener. This ADR fixes only how the two secrets `circuit/join` and `circuit/authenticate` traffic in — the join secret and the credential — are protected **at rest**.

1. **Generation.** A join secret and a credential are each a 256-bit value from the OS CSPRNG, given an identifiable prefix (`hlr_join_…` / `hlr_live_…`) so a leak scanner can spot one in the wild. Neither is ever logged; a join secret is shown to the operator exactly once, at mint.
2. **At rest, both are `HMAC-SHA-256(pepper, secret)`.** The store never keeps the plaintext value, only the HMAC digest, looked up by the public `token_id` and compared in constant time on redeem or on every `circuit/authenticate`. Argon2id is not used here — these are 256-bit random values, not human-chosen passwords, and Argon2's deliberate slowness buys nothing against a value that is already unguessable.
3. **The pepper is `HOLLER_PEPPER` (hex) or an autogenerated file.** If the environment variable is unset, `hub serve` and `hub token mint` autogenerate a 32-byte random pepper on first use, written to `HOLLER_STATE_DIR/hub/.pepper` at mode `0600`. The pepper is never stored in the same row as the digests it protects, and it is never itself logged — the shared redaction filter (`holler-proto`'s log module) treats any field named `pepper`, case-insensitively, the same way it treats `secret`, `credential`, and `authorization`.
4. **TLS is the proxy's job, full stop.** Confidentiality of the frames carrying these secrets over the wire — including `circuit/join` and `circuit/authenticate` themselves — is TLS 1.3 on `wss`, terminated by whatever sits in front of the hub's loopback `ws` listener. This ADR does not re-decide that; see [ADR 0006](ADR-0006.md) for the deployment shape and the "underlay is not identity" argument. This ADR is scoped to **at-rest** protection of the two secrets, not to the transport.
5. **An underlay is never identity.** Whether the TCP path exists over a LAN, an SSH tunnel, a tailnet, or the public internet is an underlay question, orthogonal to both this ADR and ADR 0006's proxy choice. None of them are ever treated as authentication — `circuit/join`/`circuit/authenticate` (ADR 0007) is still required regardless of which network carried the bytes, and a peer's address is never trusted as identity.

## Why

Join secrets and credentials leak the same way any bearer token does — into shell history, chat, and screenshots — so the mitigation is the standard API-token one: mint with high entropy, hash at rest with a keyed function so a stolen database alone does not recover the secrets, and keep the key (the pepper) out of the row it protects. HMAC-SHA-256 is what GitHub- and Stripe-style API tokens use for exactly this reason; Argon2id solves a different problem (a human-chosen, low-entropy password) that does not apply to a 256-bit CSPRNG value. Autogenerating the pepper on first use, rather than requiring an operator to set `HOLLER_PEPPER` before the hub will start, removes a manual step from the single-binary, single-command `hub serve` story (ADR 0001) without weakening the guarantee — the file is still 32 random bytes at `0600`, whether a human chose to override it with an env var or not.

## Consequences

- `crates/holler-hub/src/token.rs` owns pepper resolution (env, else autogenerated file) and the HMAC compare for both the join secret and the credential; this is the single place either kind of digest is computed.
- The redaction filter in `holler-proto::log` extends its existing `secret`/`credential`/`ticket`/`authorization` substring match to `pepper`, so a `--debug=noisy` trace can never print the value that would let an attacker forge every token in the store.
- Deployment security (the loopback-`ws`-plus-proxy shape, native TLS as v2 work) is not restated here; a reader who wants that lands on [ADR 0006](ADR-0006.md) directly.

## Not decided here

- The join/credential pairing model and the CLI surface that mints and lists tokens — [ADR 0007](ADR-0007.md).
- Transport confidentiality, the loopback-`ws`-only rule, and the tailnet/proxy deployment path — [ADR 0006](ADR-0006.md).
- Native TLS terminating in the hub itself — deferred to v2 by ADR 0006, unaffected by this ADR.
