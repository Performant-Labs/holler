# ADR 0011 — Address sessions, not hosts — via routable names

**Status:** accepted
**Issue:** [#12](https://github.com/Performant-Labs/holler/issues/12)
**Date:** 2026-09-09
**Depends on:** [ADR 0005](ADR-0005.md)
**Supersedes:** `holler-server` ADR-0007 (address sessions, not hosts)

## Decision

The unit a hub-level command names is a **session**, never a host or a connection. `holler-server` ADR-0007 established this for flat, per-hub-unique session names (`alpha`); this ADR keeps the semantic and defers its *shape* entirely to [ADR 0005](ADR-0005.md), because in this repo a session's address is hierarchical (`<label>/<session>`) and explicitly decoupled from whichever connection currently hosts it.

1. **`say`, `interrupt`, `roster`, and remote `query` all take a session address, never a host, a client id, or a raw connection handle** as the primary argument. A body process may host many sessions at once (the original v1 gate: two sessions on one remote body), and a host identity is metadata on the roster row, never the key a command looks up.
2. **The address grammar, the label/session split, and name-vs-locator stability are ADR 0005's, not re-decided here.** This ADR is the slot that carries forward the *principle* — address sessions, not hosts — from the legacy repo; the concrete grammar that principle now uses (`<label>/<session>`, prefix-matchable, independent of the connection carrying it) was already fixed when ADR 0005 was written and is referenced rather than restated.
3. **Collision policy is likewise ADR 0005's and ADR 0010's**, not this ADR's: what happens when a `session/presence` claims a name already held is a roster-state question (ADR 0010 §6), built on the addressing scheme this ADR points at (ADR 0005).

## Why

`holler-server` ADR-0007's reasoning still holds without modification: an operator wants to say `say alpha`, not `say kiwi:4096`, because the session — not the machine, and not the socket — is the thing being talked to, and a session should not need to change how it is addressed just because its host reconnected under a new client id. What changed since ADR-0007 is not the *principle* but the *vocabulary* available to express it: flat, per-hub-unique names could not express "which label minted this session" or support prefix-scoped listing and (later) prefix-scoped tokens. Rather than re-litigate that shape here, this ADR keeps the one-line principle in its own slot — so a reader who only wants "why do we address sessions and not hosts" has a short answer — and points everything about the actual grammar at ADR 0005, which is where that grammar was designed and where its consequences (newtypes, wire fields, error codes) live.

## Consequences

- No command in the CLI surface (ADR 0003) takes a bare host or connection identifier as its primary target; `TARGET` resolution for remote `query` tries `label/session` → `label` → `client id` → `token id`, in that order, with ambiguity always an error rather than a guess.
- A body reconnecting under a new socket, and therefore a new `client_id`, does not require any caller-visible change — every in-flight and future `say`/`interrupt`/`query` for that session continues to resolve through its stable routable name.
- This ADR intentionally carries **no** independent "Consequences for `holler-proto`" section, because the newtypes, wire fields, and error codes that implement addressing all belong to ADR 0005; splitting them here would create two normative sources for one mechanism.

## Not decided here

- The address grammar itself — labels, bare session names, routable names, prefix matching — [ADR 0005](ADR-0005.md).
- Collision handling when a claimed name is already held — [ADR 0005](ADR-0005.md) §5 and [ADR 0010](ADR-0010.md) §6.
- Prefix-scoped tokens and prefix routing beyond `roster --prefix` listing — reserved grammar in ADR 0005, not implemented by any ADR yet.
