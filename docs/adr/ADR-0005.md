# ADR 0005 — Hierarchical session names; name is not locator

**Status:** accepted
**Issue:** [#6](https://github.com/Performant-Labs/holler/issues/6)
**Date:** 2026-09-07
**Depends on:** [ADR 0004](ADR-0004.md)
**Supersedes:** server ADR-0007 (flat session names)
**Executes:** [holler-server#318](https://github.com/Performant-Labs/holler-server/issues/318) (items 1–2)

## Decision

Session names in protocol v2 are **hierarchical** and **prefix-matchable**, and a session's **routable name is independent of the connection currently hosting it**. The address is a stable identity; the thing that carries it (the socket) is not. This keeps the one semantic server ADR-0007 already had — **address sessions, not hosts** — and adds the structure that flat names never could.

### 1. Labels — chosen at mint, unique per hub

- A **label** is chosen when the hub mints a token: `holler hub token mint --label L`.
- **Grammar:** `^[a-z0-9][a-z0-9-]{0,31}$` — one to 32 characters, starting alphanumeric, then lowercase letters, digits, or hyphens.
- **Labels are unique per hub.** Minting a token whose label is already in use is **refused with exit 3** (`label already in use`). The label is a hub-local namespace root, so a collision would silently re-route traffic.

### 2. Session names — bare on the body, qualified on the hub

- A **body** advertises **bare** session names (`alpha`), grammar `^[a-z0-9][a-z0-9-]{0,31}$` (the same shape as a label).
- The **hub's routable name** for that session is `<label>/<session>` (e.g. `io/alpha`) — the label of the body's token, joined to the bare name the body sent.
- **Bodies never send the label.** The label travels with the **authenticated token**, not the frame; the hub reads it off the connection it already authenticated. This is the same "identity is the connection" rule ADR 0004 applies to v1's dropped `from` — the label is identity, so it is not on the wire.

### 3. Name vs locator

The **roster row is keyed by routable name**. The `client_id`, peer address, and connection handle are **locator fields on that row**, and any of them **may change across a reconnect without changing the name**. Consequently every `say` / `interrupt` / `query` `TARGET` resolves a **name → the current locator at call time**; a command is never issued to a locator it was handed earlier. A body that drops and re-joins keeps its `io/alpha` name and simply gets a new row locator under it.

### 4. Prefix operations (the grammar is the point)

- `roster --json` supports `--prefix io/` — list every session under a label (and, transitively, under a deeper prefix).
- `hub query io/ …` is **reserved**: in v1 it returns an error (**not implemented**), but the **grammar exists** so that prefix-scoped **tokens** and **routing** can land later **without a wire change**. The shape is in the spec now so nothing downstream has to guess it.

### 5. Collision policy (and why #243 cannot recur)

- A `session/presence` advertising a routable name `<label>/<session>` that is **already held by a different token** is **rejected** with error **`-32003 unknown_session`** and `data: {"reason": "name held by another body"}`.
- The **same token re-advertising its own name always succeeds** — that is the **reconnect case**, and it must never read as a collision.
- Because **presence is periodic** (the Roster story), a rejected claim is **retried automatically** on the next beat. The failure mode behind [holler-server#243] — a lost presence race that permanently hid a session — **cannot recur**: a rejected claim is transient and re-asserted, so a session is hidden only as long as the genuine conflict lasts, never permanently.

### 6. Bare-name convenience

The CLI accepts a **bare** `alpha` when **exactly one** `*/alpha` exists in the roster. When two or more do, it is **ambiguous**: **exit 2** with the candidates listed one per line. (This is the rule [ADR 0003](ADR-0003.md) already describes for `SESSION` / `TARGET`; this ADR is the slot that owns it.)

## Why

**SLIM's** and **NATS's** subjects are hierarchical and **prefix-aggregatable**: a subscriber on `io/` gets every `io/<session>` without a line per session, and a prefix both routes and scopes in one token. Flat names cannot express that, and — the practical reason to do it now — **flat names cannot be retrofitted once config files and operator scripts exist**. The label/`<label>/<session>` split is a grammar decision that is cheap to make before the surface is frozen and expensive to undo after.

## Consequences

- **`holler-proto` owns the newtypes.** The label, bare session name, and routable name each become their own newtype (distinct at the type level, so a label can't be spliced where a session name is expected). **Exposing those newtypes is a later story** (the `docs/protocol/v2.md` / `holler-proto` work, #331); this ADR fixes the semantics they encode.
- **The roster row is keyed by routable name**, with `client_id` / peer address / connection handle as **mutable locator fields** on the row. A reconnect changes the locator, never the key.
- **The wire carries the bare name only.** The label is a property of the authenticated token, not a field on the frame — so adding it to the wire (and the routing it enables) is a **later, separate** change. The name/locator split is what makes that change additive rather than a re-key.
- **Error `-32003 unknown_session`** is added to the application error range ADR 0004 reserves (`-32000..-32099`), with `data.code` carrying the Holler string and `data.reason` the human-facing cause (`name held by another body`).

## Kept, not retired

From server ADR-0007 this ADR keeps the core semantic — **address sessions, not hosts**: a command names a session, and the hub finds whatever host is currently hosting it. What changes is the *shape* of the name (flat → hierarchical) and the *stability* of the address (now independent of the connection). Nothing else from ADR-0007 survives.

## Not decided here

- **Prefix-scoped tokens** and **prefix routing** (the `hub query io/ …` behaviour, deeper than `--prefix` listing) — the grammar is reserved here; the behaviour lands in the routing story.
- **The `holler-proto` newtypes** (`Label` / `SessionName` / `RoutableName`) and their on-wire serialization — the protocol story (#331).
- **The Roster story** — the periodic `session/presence` beat that makes the §5 retry automatic, and the `roster` output shape.
