# ADR 0002 — Decisions retired from holler-server and holler-client

**Status:** accepted
**Issue:** [#3](https://github.com/Performant-Labs/holler/issues/3)
**Date:** 2026-09-07
**Depends on:** [ADR 0001](ADR-0001.md)

## Decision

This rebuild **deliberately retires** a set of decisions made under the old `holler-server` / `holler-client` split. Each row below is retired **with a reason**, so nobody re-litigates it or silently reintroduces it. The replacement is the ADR that now owns the decision (or "deferred" / "declined" where there is no v1 replacement).

| Retired decision | Where it lived | Replaced by | Why |
|---|---|---|---|
| Two binaries (`holler-server`, `holler`) | server ADR-0002, both Cargo.toml | ADR 0001 | Install-time role split; verb collisions; two release matrices |
| Custom envelope `{v,type,id,ts,from,body}` (Holler protocol v1) | server ADR-0009, `docs/protocol/v1.md` | ADR 0004 (JSON-RPC 2.0, protocol v2) | Every neighbouring hop (ACP, A2A, MCP) is JSON-RPC; correlation/notification semantics come free; thinner A2A bridge |
| Dedicated `join`/`join_ok` frame types (ADR-0015) | server ADR-0015 | `circuit/join` JSON-RPC request | Same behaviour, standard shape |
| SemVer per crate, independent per repo (ADR-0014 / client ADR-0003) | both repos | ADR 0003 (one released artifact, one version) | ADR-0014's own premise ("each repo builds one crate") is gone; only the CLI/`--json`/on-disk surfaces are compatibility surfaces and there is now one of each |
| Flat session names (`alpha`) | server ADR-0007 | ADR 0005 (`<label>/<session>`) | Prefix-scoped routing and tokens; collision handling by construction |
| One-shot `presence` at connect | client `connection.rs`, server #52 | periodic `session/presence` (Roster story) | Lost race permanently hid a session (holler-server#243) |
| `holler-server client list` / `client detach` aliases | server ADR-0003 | `hub token list` / `hub token delete` only | "client" is now "body"; aliases were confusing |
| SSH tunnel as the supported remote pattern (`app:local:tunnel`) | client scripts, server CHANGELOG known issue | ADR 0006 (tailnet / reverse proxy) | Zero-code TLS via `tailscale serve` or any proxy; tunnel was a stopgap until `wss` |
| Native TLS in the server (holler-server#205) as a v1 requirement | server ADR-0004/0010 follow-on | deferred to v2 (ADR 0006) | Proxy path is compliant with the loopback-`ws` rule |
| ACP v1 pinned; "do not wait on v2" (server ADR-0012/0013) | server ADR-0012 | ACP v2 (`agent-client-protocol` 2.1.0) | v2 is stable; it provides `requires_action`, which is the `blocked` state |
| `test-hlrsvr` / `test-hlrclnt` labels and `hlrsvr-`/`hlrclnt-` ID prefixes | server #98 | `hlr-NNNN`, `Applies to: hub/body/both`, labels `test-hub`/`test-body` | One binary, one catalog |
| `<repo>:` prefix in the catalog `Automation` field | server #98 | crate-aware forms (Master testing issue) | One repo |
| Windows on the CI matrix | both `ci.yml` (already off) | stays off; tracked as a deferred story | Real compile break (client#60) and runner timing (server#302); not v1 |
| Claude Code harness (holler-client#123) | client epic | deferred | Multi-harness is the most commoditised item; ACP v2 driver makes it a config row later |
| Optional single-last-reply buffer (holler-server#53) | research memo | declined | Ask-again is right-sized for 1:1 hub↔body |
| SIGTERM "not currently caught" (hlrsvr-1305) | server io tests | SIGTERM handled like SIGINT (I/O test story) | A documented gap is not a feature |

## Kept, not retired

These decisions **survive** the rebuild unchanged. Each is re-recorded as its own ADR in the Port ADRs story; this list exists so the retirement table above is read as *these specific* decisions go away, and only those.

- join-then-credential pairing
- HMAC-SHA-256 + pepper at rest
- interrupt-is-control-and-session-survives
- presence-is-status with TTL tri-state
- address-sessions-not-hosts
- harnesses-are-config-not-plugins
- loopback-`ws`-only
- no-model-answers-`support`
- AGPL-3.0-or-later
- Rust because of the official ACP SDK
- attach mode

## Not decided here

The forward ADRs this table points at — ADR 0003 (one released artifact, one version), ADR 0004 (JSON-RPC 2.0, protocol v2), ADR 0005 (`<label>/<session>` addressing), ADR 0006 (tailnet / reverse proxy) — are decided in their own slots, not here.
