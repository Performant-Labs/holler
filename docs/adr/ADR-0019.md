# ADR 0019 — Noise XK mutual-authentication handshake, a pairing SAS, and the protocol 3 hard re-pair

**Status:** accepted
**Issue:** [#20](https://github.com/Performant-Labs/holler/issues/20) (claims this reserved slot for [#321](https://github.com/Performant-Labs/holler/issues/321)/[#338](https://github.com/Performant-Labs/holler/issues/338)/[#339](https://github.com/Performant-Labs/holler/issues/339)/[#340](https://github.com/Performant-Labs/holler/issues/340))
**Date:** 2026-09-16
**Depends on:** [ADR 0004](ADR-0004.md), [ADR 0006](ADR-0006.md), [ADR 0018](ADR-0018.md)
**Supersedes (in part):** [ADR 0007](ADR-0007.md) §3 and [ADR 0018](ADR-0018.md)'s `circuit/prove` decision — the Ed25519-signed-transcript proof of possession (#323) is replaced by an actual Noise XK authenticated key exchange. Also amends [ADR 0006](ADR-0006.md) point 6 and [ADR 0008](ADR-0008.md) — see each ADR's own "Amended"/"Narrowed by" line rather than restating the change here.

## Decision

**#338 — Noise XK handshake core, replacing the challenge-response.** `circuit/authenticate` → `circuit/prove` now carries a 3-message `Noise_XK_25519_ChaChaPoly_BLAKE2s` handshake (`holler_proto::noise::HandshakeXk`, built on the `snow` crate rather than hand-rolled), in place of #323's Ed25519-signed transcript. The **body is the Noise initiator** — it already knows the hub's static key (`hub_pubkey`, pinned at `body join`) in advance, exactly the `K` in `XK`, so a body dialing a hub whose real key does not match what it pinned fails at message 1, before `circuit/hello` ever runs. The **hub is the responder** — it learns the body's static key only from message 3, and compares it against the token's registered `body_x25519_pubkey`; that comparison, not the handshake completing, is what ties the proof to *this* token. The prologue binds `token_id ‖ advertised_url ‖ protocol_version`, so a captured transcript cannot be replayed into a different token, endpoint, or protocol context. No extra freshness nonce is needed: the responder's own message 2 always carries a fresh ephemeral key nothing earlier in the transcript determines, so a captured message 3 can never verify against a fresh handshake.

**#339 — a pairing SAS.** Immediately after a handshake completes, both sides independently derive a short authentication string — HKDF-SHA256 over the handshake hash `h`, under the versioned, distinct label `holler-sas-v1` (`holler_proto::sas::derive_sas`), rendered as 6 decimal digits (`NNN-NNN`). It is never transmitted; each side logs its own value for the operator to compare by eye. This closes the one direction the pinned hub key alone does not cover: the hub has no way to tell *which* body redeemed a join token, so if the join line leaked before the intended body used it, a matching SAS on both consoles is the operator's confirmation that hub and body completed the handshake with *each other*.

**#340 — protocol 3, a deliberate hard re-pair.** `PROTOCOL_VERSION`/`PROTOCOL_MIN`/`PROTOCOL_MAX` bump from 2 to 3. `circuit/authenticate.protocol` is checked against the supported range **before any Noise processing begins** — a mismatched body is refused with a specific `-32000` naming the mismatch and directing the operator to upgrade and re-run `body join`, not an opaque Noise handshake failure (which the prologue's own `protocol_version` binding would also eventually produce, but without a clear cause) and not a silent downgrade. `circuit/hello`'s existing `protocol` check is unchanged and stays as a second, defense-in-depth layer. Any body still on protocol 2 must re-pair; per ADR 0007's original framing (echoed in ADR 0018), this break is free before [v0.1.0](https://github.com/Performant-Labs/holler/issues/319) and expensive after — landed before any release.

## Why

Holler's topology is an exact fit for Noise XK: the body dials out (initiator), the hub listens (responder), and the operator already carries a string hub→body out of band (the join line) — precisely what `XK`'s pre-shared responder key requires, and precisely what ADR 0018's `#322` hub-identity decision was chosen ahead of time to feed (see that ADR's own "why two different primitives" reasoning). Using `snow`, a maintained, independently-reviewed Noise implementation, rather than hand-rolling the handshake, keeps this repo out of the business of writing its own AEAD/DH composition. A full AKE also produces something ADR 0018's signed-transcript design could not: a shared, secret handshake hash neither side transmits, which is exactly the raw material a pairing SAS needs.

## Consequences

- `crates/holler-proto/src/noise.rs` (new) and `sas.rs` (new); wiring lives in `crates/holler-hub/src/circuit.rs`, `circuit/auth.rs`, and `crates/holler-body/src/connection/handshake.rs`. `holler_proto::transcript` (the #323 transcript builder this design has no use for) is removed.
- `token.rs`'s `Record` fails closed on a bound record with no `body_x25519_pubkey` — every bound token now expects the identity material this handshake authenticates against.
- `docs/protocol/v2.md` §3 documents the full wire shape (message framing, the `-32000`/`-32002` error rows, the SAS derivation) — this ADR does not repeat it.
- **This handshake is authentication only, not session encryption.** `circuit/authenticate`/`circuit/prove` establish that hub and body hold the identities they claim; nothing about `session/…`, `query/…`, or `circuit/ping` traffic changes — see "Not decided here" and [ADR 0006](ADR-0006.md)'s amended point 6. A reader should not infer that the proxy's exposure to live conversation traffic has narrowed because this ADR exists.
- **Known gap, tracked separately:** the SAS's own "requires explicit operator confirmation" is not machine-enforced by #339 — it is logged and left to the operator to read and compare, deliberately, because `body run`'s connection loop is also the automated reconnect path every e2e test and unattended daemon depends on, and a blocking prompt there would hang both. A persisted, pairing-only (not per-reconnect) confirmation gate is [#351](https://github.com/Performant-Labs/holler/issues/351).

## Not decided here

- **Session/transport encryption of the live connection.** `HandshakeXk` deliberately exposes no transport/session cipher type; `session/…`/`query/…`/`circuit/ping` traffic after `circuit/hello` is unchanged — plain JSON-RPC frames over whatever the deployed transport is (ADR 0006). A future issue extending this same handshake into a transport cipher over the live socket would supersede this line, not this ADR's own scope.
- The operator-confirmation gate for the SAS — [#351](https://github.com/Performant-Labs/holler/issues/351).
- Native hub TLS and its certificate model — [ADR 0006](ADR-0006.md), v2, unaffected by this ADR.
